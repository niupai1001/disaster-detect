# 03 验证协议（E0 独立指标 S_intra）

**结论**：E0 使用独立命名的 `S_intra=(L_A+L_B1)/2`，与历史 `S=(A+B)/2、B=(B1+B2)/2` 完全隔离；
B2 缺席不再阻塞验证，缺失来源不会被静默重归一化，非有限值/缺案例显式报错。旧函数、旧指标名与旧面板加载路径
原样保留。

## 1. 指标定义

```text
S_intra = (L_A + L_B1) / 2                    # 首轮实验权重 1/2 + 1/2，待随正式配置批准
L_A     = 等权平均(来源) [ 平均(观测) [ 平均(A 案例) ] ]
L_B1    = 等权平均(来源) [ 平均(观测) [ 0.5·单隐藏均值 + 0.5·多隐藏均值 ] ]
多隐藏均值 = 2..C-1 各隐藏数量先等权，再对同一数量内的案例取均值
案例损失 = 该案例各受支持目标波段的 TRAIN 归一化像元 NMSE 的平均
```

- A：每个监督目标先按波段算 NMSE，再在同一观测内聚合，再在同一来源内聚合，最后来源等权。
- B1：单隐藏与多隐藏各占 1/2；多隐藏按隐藏数量 2..C−1 等权；观测内、来源内聚合；来源之间等权。
- P60/P120 的重复是**案例**，不构成额外层级。
- 不允许"因为某来源没有监督支持就重新归一化"：A 与 B1 的来源集合必须相同，否则直接
  `ValidationUnavailable`；任一案例缺失、重复 `case_id`、非有限损失、B1 缺少单隐藏或多隐藏的某个数量，
  都显式失败而不是填 0。
- 传入 B2 案例会被拒绝（`S_intra is the A+B1 protocol; B2 cases must not enter`），因此 E0 的指标
  在结构上不可能依赖 B2。

实现：`validation_metric.aggregate_intra_validation`（新函数，约 30 行，复用既有的层级聚合辅助函数）。
旧 `aggregate_validation` 未改一行，仍是 `S=(A+B)/2、B=(B1+B2)/2`、仍要求 B2 存在。

## 2. 固定验证面板

面板文件：`frozen/validation_panels.json`（哈希绑定在 `config_optical_selfsup_v1.json` 与 checkpoint 的
`frozen_ids` 中）。

| 项 | 值 |
|---|---|
| 观测数 | 3（Sentinel-2 十波段 116×116 ×1；Landsat 七波段 49×49 ×2） |
| 案例数 | 54（每个观测 × 每个 P：1 个 A + 2 个单隐藏 + 每个多隐藏数量 1 个） |
| P | 60 m 与 120 m 各一半 |
| A 遮盖 | 与训练同一条冻结矩形规则，`target_patch_fraction=0.5`、长宽比 log-uniform[0.5,2.0]、patch 对齐 |
| B1 单隐藏 | 按**实测 SRF 加权中心波长**排序后取最低与最高两个波段 |
| B1 多隐藏 | 每个隐藏数量 k=2..C−1 取一个循环连续窗口（按同一波长顺序），保证至少留一个可见波段 |
| 成员选择规则 | 每个来源取"波段最丰富、且原生场景像素不超过训练池上限"的最小场景，按 id 确定性排序；规则写入面板 `builder.selection_rule` |
| 统计量 | 只用 TRAIN-only `statistics.json`；VAL 不参与拟合 |
| 配对 | `pair_admissions` 为空，没有 B2 案例 |

**为什么只选了 3 个观测**：面板要满足"每个观测覆盖 2..C−1 全部隐藏数量"，十波段观测就必须有 8 个多隐藏案例；
而 VAL 里满足训练池像素上限的十波段 Sentinel-2 场景只有 1 个（116×116）。其余十波段 VAL 场景是 133–459 像素，
超出训练池上限，若纳入会测量模型从未训练过的场景规模。这一点在 `09_remaining_decisions.md` 中列为可批准项：
若要扩大 S2 面板代表性，需要同时放宽训练池上限或提供裁剪协议。

**成本**：本机 FP32、cell-indexed 读出下，一次完整面板采集的实测耗时与显存见
`evidence/preflight_no_update.json/panel`；它按 250 更新一次的固定周期执行，是训练预算的一部分。

## 3. 验证执行约束（已实现并测试）

- 固定成员、固定遮盖、固定 SRF/数据版本、固定面板：`FrozenValidationPanels.__init__` 校验面板文件哈希、
  release 身份、成员版本/角色/波段、Merge 配方，`iter_views` 每次检查文件未被改动。
- 验证时**不更新参数、不步进优化器、不改变 RNG**：`collect` 保存并恢复 Python/NumPy/Torch/CUDA 随机状态、
  模块训练态，返回 `optimizer_updates=0`。
- 验证只读 TRAIN 统计量；VAL 自身的统计量不参与（`engineering_train_stds` 声明 `TRAIN-only`）。
- 失败、缺失、非有限值显式报错：面板采集把不可用原因写入 `metric_status`，runner 侧 `panel_validator`
  遇到不可用直接抛 `ValidationUnavailable`，不会用占位值继续调度。
- 验证使用的读出路径与训练一致（cell-indexed 精确读出，见 `05_performance_comparison.json` 的数值回归）。

## 4. 附加研究指标（不增加额外前向）

面板采集与真实无更新诊断一次性产出、随证据保存：

- 按传感器/来源划分的 A、B1 损失（层级均值，与标量同口径）；
- P60 与 P120 分别的 A、B1 损失；
- 按隐藏数量、按波段划分的 B1 损失；
- Token 数、监督像元数、无支持像元数（逐案例）；
- 训练侧梯度统计（每个模块的范数、裁剪前总范数、裁剪后范数）——在无更新诊断中测量，
  不进入验证前向。

这些是诊断与论文分析用途，不参与选模；选模只看 `S_intra`（以及冻结的早停规则）。

## 5. 与旧指标的隔离

| 项 | 旧 | 新 |
|---|---|---|
| 名称 | `S`、`B` | `S_intra` |
| 公式 | `S=(A+B)/2`，`B=(B1+B2)/2` | `S_intra=(A+B1)/2` |
| B2 | 必需（缺则标量不可用） | 出现即报错 |
| 函数 | `aggregate_validation`（未改） | `aggregate_intra_validation`（新增） |
| 面板 | `frozen_validation_panels_v1` 通用 | 同一文件格式，B2 配对表为空 |
| 配置 | `config.json`（旧门禁 14 项） | `config_optical_selfsup_v1.json`（E0 门禁 8 项） |

旧指标仍可在旧配置/旧面板上运行并通过原有测试；新指标不会读取旧配置的权重，也不共享函数名。

## 6. 边界

- `S_intra` 的 1/2 + 1/2 是**首轮建议权重**，尚未批准；`weights` 字段随指标一起返回，便于审计。
- 面板的 S2 代表性问题见第 2 节；Landsat 面板只有 7 波段小场景（VAL 中 Landsat 全部为 49–54 像素）。
- 指标本身不衡量跨传感器泛化：E0 的 A/B1 都是同观测任务，跨源能力仍需 B2 或下游任务评估。
- 验证只在 VAL 上进行；当前发布没有 TEST/GUARD，不能声称独立测试集结论。
