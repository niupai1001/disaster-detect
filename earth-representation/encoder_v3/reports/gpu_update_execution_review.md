# 真实GPU更新与恢复检查：执行提案

成员与固定验证面板已经获得预检用途确认。以下设置已获用户确认，并完成8次检查；实际耗时约203秒，峰值分配显存约2.35GB。

- 设备：仅CUDA 0；执行前确认资源可用，不停止其他任务，也不触碰CUDA 1。
- 精度：FP32参照。有效批量始终为8，观测微批量1，局部批量64，像元块512。比较旧Token几何索引与批量原生像元索引；模型、数据和监督相同。
- 共同优化条件：100次Warmup至3e-4，weight decay 0.04，裁剪3，β=(0.9,0.999)，ε=1e-8；所有偏置（含注意力in_proj_bias）和LayerNorm不衰减。
- 每种优化器4次实际更新：旧路径第1次、新路径第1次、新路径连续第2次、从第1次检查点恢复后的第2次。两种优化器共8次，全部占用既定400次预算，每种后续最多剩196次拟合更新；不会额外增加训练组或预算。
- 上限提案：本次检查总墙钟30分钟、模型峰值分配显存12GiB、产物2GiB。越界停止自己的检查进程；不自动重算，也不回收不确定更新的预算。
- 交付：完整预测、损失、梯度、一次更新后的参数/优化器状态差异，以及恢复后的下一次成员、遮盖、目标、课程、LR、随机状态及参数差异。A/B检查不启用EMA/JEPA，不把其缺席记为通过。

检查先给出实测误差，数值容差仍由后续评审确认，不因为得到小误差就自动采用加速路径。本提案只覆盖8次更新与恢复检查；其余拟合预检、正式训练和任务头训练均不会随之启动。

可执行入口及预算账本已验证：8次预留均完成，无不确定预留；剩余392次，两种优化器各196次。检查点、来源和代码身份已保存，未覆盖历史检查点。
