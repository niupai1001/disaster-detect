# 项目协作规则：先定位，再认领，最后回写

继承[工作区用户偏好](../AGENTS.md)。中文回答，直接完成授权工作；失败、未验证、受阻如实标注。此文件只维护工作方法，不记录不断变化的实验成绩。

## 开工的最小读取

1. 只读 `docs/RESEARCH_INDEX.md` 开头的“新 Agent 最小接力”（截止 `MIN_HANDOFF_END`），不要默认全文读入口。
2. 运行 `python -X utf8 scripts/manage_agent_work.py list`，检查谁做过、谁正在做；实验任务再查 `outputs/research_completion/status.json` 中相关命令、真实进程及产物。
3. 读取 `docs/assets/research/research_policy.json`；只选入口路由表中与任务相关的一份专题，按标题取小节。阶段先用 `query_research.py --stage <id>`；不默认读完整台账或机器索引。
4. 用 `manage_agent_work.py claim <任务ID> --owner <聊天ID> --title <工作> --scope <路径>` 认领。多个写入范围重复 `--scope`。路径相对本项目，不含 `..`；文档按整文件登记，实验至少登记输出目录。先查同一目的/配置/成员/预算已有成果，任务名不同不表示工作不同。

## 哪个来源决定什么

- 用户当前授权决定是否执行。历史文档、队列、计划或checkpoint存在不等于新训练授权。文档整理本身不扩大授权；用户明确要求完成当前整条计划时，按下述工作流规则自动接续，不恢复无关历史队列。
- `research_policy.json` 是机器可检查的稳定实验契约；阶段目标、变化、观察、比较和下一步只写 `stage_ledger.json`。
- `agent_work.json` 只记任务负责人、占用范围、交付与证据位置；不复制指标或计划全文。聊天贡献与产物作者不能无证据等同，未知作者写待核实。
- `outputs/.../status.json`、日志和实际进程表示执行情况；评价与验收文件表示完成证据。进程退出不等于验收完成；任何冲突先保留证据、纠正台账，不凭文档日期猜测。
- 研究文档是解释与索引，不另写一套事实。`<!-- ..._START/END -->` 标记内为脚本生成内容，只改对应JSON/生成器后刷新。

## 当前实验契约摘要

默认九事件2223块训练，广岛448＋特里苏尔221块开发验证，seed1234；机器标识 `event_ood_v4r1`。DEV按二事件等权IoU选模，反复用于研发，不称盲测。十波段沿用559块训练核心拟合的 `stats_core25.json`；新增输入统计只用合法TRAIN拟合。Italy为指定诊断，NewZealand为保留评价，均不用于研发训练或常规选模。完整成员锁、输入、初始化与历史接触限制以共享协议和数据文档为准。

四折只留历史诊断；不补齐四折作为默认前置。官方新实验等项目候选明显进步并冻结后再安排。禁止用包含留出事件监督的权重冒充无泄漏起点。旧路径和配置字段保持兼容。

交给执行者必须包含：实际配置与全部覆盖、成员清单、统计及来源、观测期/波段/地形、初始化、停止预算与学习率日程、选模、输出、验收和回写位置。未适配明确写待实现，不拿四折或官方配置替代。

训练前对实际配置及每个 `--set` 执行 `scripts/check_research_protocol.py --config <配置>`。此只读预检不加载模型或重算图像统计，不能替代运行验收。工程smoke不计正式成绩。当前计划与旧队列预算分别查台账与实时状态，不能中途按新计划改旧进程。

## 完整工作流自动接续

- 用户明确授权完成当前计划或要求“所有流程顺序推进”后，该授权覆盖已确认目标、作业矩阵、数据版本与总预算内的全部依赖阶段。阶段门禁是技术验收条件，不是要求用户再次说“开始下一阶段”的许可门槛。旧任务书中的“逐阶段另行授权／完成后等待”若与用户最新全流程授权冲突，必须由持有者同步改写台账、生成计划、提示词、运行状态及已有监测指令，不能继续据旧文案停工。
- 执行负责人维护唯一台账中的依赖图和当前作业：已完成且验收通过→立即检查下一依赖阶段→条件具备即启动并验证实际推进。按真实依赖而非编号盲排；有先行冻结消费者等前置时先做前置，不重复计预算。正在运行的阶段保持原有效配置，不中途按新文档改写。
- 工程与训练仍按原分工负责整条工作流。工程Agent提前准备后续入口、配置、预检、测试和独立release；训练Agent并行准备验收，在前一阶段完成后自动验收接续。缺入口、可修复BUG、失效锁、停止进程、显存调度等问题主动定位修复和恢复，不退回“等待用户继续”。共享显存依既有用户要求和实际容量处理，不能以等待全卡空闲代替推进。
- 条件性实验严格按已确认条件执行；缺合法标签/配对不足等不满足时记录SKIPPED及证据，再推进其余独立可执行分支，不造数据、不降低准入、不挪用空余预算。强制前置失败则继续合理排障；确实无法满足时报告受影响分支、原因、已尝试措施和必要外部动作，不能把普通工程难题当作新的授权请求。
- 跨阶段必须保持冻结成员、独立初始化/选模、release与验收绑定以及逐作业预算。新工程不得原地破坏运行中或可恢复旧作业的源码/配置，使用隔离版本；修复后重新预检验收。只有需要新增目标/实验、超预算、改变关键科学设置或冻结成员，或有无法安全处理的外部阻断，才向用户提出具体决策。
- 完成一个阶段、发布一个release、进程启动、发出告警、设置监测或最后一项训练进程退出，都不代表整项工作完成。必须核对全部已授权必做项及条件项的完成/有据跳过、评价/冻结/预算/恢复/曲线/产物，完成规定比较与固定文档回写后再结束。监测任务跟随当前完整授权范围，复用已有任务，不能残留只看前一阶段或禁止已授权后续阶段的旧限制。

## 训练运行、故障与恢复责任

- 训练认领者负责已授权作业的启动、实际推进、异常排查、安全恢复及最终验收。启动进程、发现停滞或设置定时检查均不表示任务完成；只有全部已授权作业完成且产物核对通过，或存在明确外部阻断，才交付结束状态。按已授权完整工作流自动接续，不扩展到计划外阶段。
- 状态须来自实际进程身份、命令、曲线步数/写入时间、完整checkpoint与评价阶段，不能沿用旧RUNNING记录，也不能以进程存在或GPU利用率为唯一依据。超过预期单步/评价/保存时长仍无推进时立即查日志、CPU/I/O和阶段位置；没有可用基准时，连续10分钟无任何有效进度即触发排查，不等待下一个半小时探查。
- 对已授权作业，原参数/数据/预算内的故障诊断和断点恢复属于执行责任，不重复向用户申请“是否恢复”。恢复前核对原PID实际命令、锁归属、同一release/配置/成员及完整断点，保留故障证据；确认为本任务挂死时可只终止对应进程，不干预其他任务。失效锁须核实后处理，不能绕过锁另起重复训练。
- 必须恢复模型、优化器、调度进度、RNG及采样游标或其等价确定性状态，保持原停止预算；保存到临时文件而未完成原子提交的checkpoint不当完整断点。连续重启同一故障无进展时停止盲重启、继续定位原因，不以多次启动替代排障。代码问题交工程修复并重新核验release，不在运行进程读取的绑定源码上原地修改或伪造旧验收。
- 恢复后至少两次独立采样确认步数增长、有效loss及checkpoint提交，再将状态改为已恢复，并记录PID/启动命令/断点/原因或未确认项。显存可承受且用户允许共享时不等待全卡空闲；本任务锁用于避免重复作业，成本测量另按隔离口径报告。
- 若用户要求持续检查，应更新已有监测任务，使其在已授权边界内实际诊断、恢复并核验，不将任务永久限制为只报告恢复条件。不得重复建立同目的监测。检查本身不扩大授权，但须推进用户已经授权且门禁通过的后续阶段；权限、损坏断点等无法安全解决的阻断必须报告具体失败证据、已尝试措施与所需外部动作，不能静默保留假运行状态。

## 写到哪里、如何结束

按[入口维护路由](docs/RESEARCH_INDEX.md#文档与维护路由)更新：数据/指标解释去数据文档，组件连接/监督/实际加载去模型文档，计划和阶段事实去台账。研究正文固定四份；`reporting_style.md` 是写作规范，协作登记是操作记录，均不另写研究报告。不要新建日期/批次报告或平行阶段总结。

共享文件写前重读目标小节，增量修改；先认领再修改，不覆盖别人的全文件。登记器用排他锁和原子替换串行写入，拒绝重复任务与活动范围冲突。锁遗留或持有者失联时先核实，受阻任务继续前也要核查登记；不按时间自动抢占。不绕过登记锁直接改JSON。该机制依赖每个Agent遵守，不能拦截绕过脚本的编辑或外部启动器。

完成顺序：保存配置/命令/哈希/逐步曲线与评价 → 更新台账相关阶段 → 刷新生成区 → 更新专题解释与证据链接 → 验证 → `manage_agent_work.py finish <任务ID> --owner <聊天ID> --evidence <产物路径> --note <做了什么及未验证项>`。受阻用 `block` 并写原因、下一步和证据。只改文档时无需重训。

运行 `python -X utf8 scripts/query_research.py --refresh-stages` 刷新阶段、历史比较、地形结构表与计划；完成后检查四份文档链接及生成幂等性。只有新增/改变run索引时才运行 `build_research_inventory.py --no-figures`，不要为文档整理重扫权重或推理。

结果报告与术语细则集中在[reporting_style.md](docs/reporting_style.md)。不再把新纠正按日期追加在本文件末尾；直接替换被纠正的规则，历史原文保留在归档。
