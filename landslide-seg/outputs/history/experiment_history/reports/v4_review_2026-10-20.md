协议执行没有问题（零泄漏、零 FINAL 外泄、算术全对），三批实验也各自给出了干净的对照结果；

## 2. 训练轨迹：过拟合是结构性的，不是个别 run 的意外

以 `detailres_n100`（DEV 最高那条）为例，36 个评测点的完整轨迹：

| 步 | 200 | 500 | 800 | 1200 | 1800 | 2400 | 3000 | 3600 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| TRAIN IoU | 0.2754 | 0.3681 | 0.3990 | 0.4230 | 0.4560 | 0.4736 | 0.4838 | **0.4895** |
| DEV 均值 | 0.2811 | **0.3081** | 0.2732 | 0.2796 | 0.2429 | 0.2588 | 0.2424 | 0.2430 |

- TRAIN 单调上升到 0.4895，DEV 在 500 步见顶后一路走低到 0.2430。**训练与验证在 500 步之后完全解耦**。
- 这个形态在 8/10 条 run 上都成立：best_step 落在 200–1200 区间（另两条是 low-LR 2300、frozen_last 600）。在 3,600 的固定预算里，**多数 run 在最优解之后还白跑了 2,400–3,400 步**。

### 2.1 平台均值暴露了"取最大值"的偏差

对每条 run 取 ≥600 步的 DEV 均值（记作平台均值）与 best 对比：

| run | best | best@步 | 平台均值 | 平台 sd | best − 平台均值 |
|---|---:|---:|---:|---:|---:|
| detailres_n050 | 0.3112 | 400 | 0.2383 | 0.0204 | +0.0729 |
| dofa_upernet | 0.1969 | 500 | 0.1262 | 0.0146 | +0.0707 |
| detailres_n075 | 0.3143 | 400 | 0.2479 | 0.0169 | +0.0663 |
| detailres_n025 | 0.2870 | 200 | 0.2246 | 0.0148 | +0.0624 |
| detailres_n100 | 0.3081 | 500 | 0.2523 | 0.0152 | +0.0559 |
| standard_n025 | 0.2813 | 800 | 0.2268 | 0.0201 | +0.0545 |
| standard_n100 | 0.2909 | 1200 | 0.2523 | 0.0152 | +0.0385 |
| frozen_best 探针 | 0.2731 | 1100 | 0.2594 | 0.0044 | +0.0137 |
| low_encoder_lr | 0.2823 | 2300 | 0.2733 | 0.0046 | +0.0090 |
| frozen_last 探针 | 0.2463 | 600 | 0.2371 | 0.0033 | +0.0092 |

**关键读数**：`best − 平台均值` 在 0.009–0.073 之间，而各 run 之间的 best 差值只有 0.017–0.030。
也就是说，**"挑哪个 checkpoint"引入的偏差大于"用哪个模型"带来的差异**。任何基于 best 的横向排名都必须带这个免责声明。

反过来看平台均值列，排序完全变了：`low_encoder_lr 0.2733` 最高，`detailres_n100` / `standard_n100` 并列 0.2523。这不是说 low-LR 更好，而是说它**几乎不退化**（sd 只有 0.0046），而正常 LR 的 run 在塌陷。

## 3. 差异显著性：哪些比较站得住

对 10 个 run 的 per-tile 计数做配对分层 bootstrap（按事件分层、5000 次、固定种子 20261020）：

| 比较 | Δ(DEV 均值) | 95% 区间 | 逐事件同向 | 判定 |
|---|---:|---|---:|---|
| SegFormer-B0 vs DOFA+UPerNet | +0.1112 | [+0.093, +0.131] | 2/2 | **成立，幅度大** |
| 联合微调 vs 冻结末态编码器 | +0.0619 | [+0.048, +0.076] | 2/2 | **成立** |
| 联合微调 vs 冻结最优编码器 | +0.0350 | [+0.024, +0.047] | 2/2 | **成立** |
| 编码器全 LR vs 低 LR | +0.0258 | [+0.015, +0.036] | 2/2 | 区间不跨 0，但与平台均值结论相反，**待定** |
| 数据扩容 25% → 50% | +0.0241 | [+0.013, +0.034] | 2/2 | **成立** |
| detailres vs standard（同池 100%） | +0.0173 | [+0.007, +0.028] | **1/2** | 单事件驱动，**待定**（见 §4） |
| 学习曲线峰值 75% vs 100% | +0.0061 | [−0.002, +0.014] | 1/2 | **不成立（噪声）** |
| 数据扩容 50% → 100% | −0.0030 | [−0.013, +0.006] | 1/2 | **不成立（已饱和）** |

两条硬结论：

1. **数据在 1,113 块（50% 池）就饱和了。** 25%→50% 有 +0.024 的真实增益，50%→100% 是 −0.003，区间跨 0。继续加标注数据在本协议下不再有回报。
2. **"n075 池 0.3143 是学习曲线峰值"不成立。** 与 n100 的差 0.006，区间跨 0，两个事件还不同向。这条应当从报告里撤掉。

### 3.1 逐事件差值：增益几乎全部来自 hiroshima

| 比较 | hiroshima | thrissur |
|---|---:|---:|
| SegFormer-B0 vs DOFA | +0.1329 | +0.0895 |
| 联合微调 vs 冻结最优 | +0.0634 | +0.0066 |
| 编码器全 LR vs 低 LR | +0.0475 | +0.0040 |
| 数据扩容 25% → 50% | +0.0462 | +0.0020 |
| detailres vs standard | +0.0492 | **−0.0146** |
| 75% vs 100% 池 | +0.0158 | −0.0035 |

除了 DOFA（两边都明显差），**所有"提升"在 thrissur 上几乎是零或者负的**。hiroshima 是 `SEEN_DEV`——v1–v3 一直拿它做 val，逐代调参都是冲它去的。所以这个模式要么说明 thrissur 太饱和，要么说明 hiroshima 存在选择过拟合。两种都需要更多种子和第三个 dev 事件才能拆开。

## 4. 尺寸分箱归因：detailres 到底改动了什么

把 DEV 的 1,679 个标注对象按面积分箱，统计对象召回（matched / evaluable）：

| run | 1–4 px | 5–9 px | 10–19 px | 20–49 px | 50–199 px | ≥200 px |
|---|---:|---:|---:|---:|---:|---:|
| detailres_n100 | 0.10 (8/77) | **0.31 (23/75)** | **0.35 (35/101)** | **0.50 (375/754)** | 0.64 (368/573) | 0.67 (66/99) |
| detailres_n075 | 0.10 (8/77) | 0.19 (14/75) | 0.32 (32/101) | 0.45 (339/754) | 0.62 (354/573) | 0.63 (62/99) |
| standard_n100 | 0.06 (5/77) | 0.11 (8/75) | 0.13 (13/101) | 0.30 (226/754) | 0.53 (304/573) | 0.65 (64/99) |
| frozen_best 探针 | 0.08 (6/77) | 0.11 (8/75) | 0.10 (10/101) | 0.29 (216/754) | 0.53 (301/573) | 0.64 (63/99) |
| DOFA+UPerNet | 0.01 (1/77) | 0.03 (2/75) | 0.06 (6/101) | 0.17 (125/754) | 0.36 (209/573) | 0.41 (41/99) |

三个可以直接用的判断：

**(a) detailres 的作用是真实且可解释的，但它作用在 5–49 px。**
5–9 px 从 0.11 提到 0.31（+15 个对象），10–19 px 从 0.13 提到 0.35（+22 个），20–49 px 从 0.30 提到 0.50（+149 个）。
而 ≥200 px 是 0.65 → 0.67，基本没动。这正是"保留更细的解码器特征分辨率"应该有的效果，也解释了为什么总量指标只涨 0.017——大目标本来就已经做对了，小目标占比又小。

**(b) thrissur 在结构上无法检验这个效应。**
thrissur 的 265 个对象里，1–4 px 和 5–9 px 都是 **0 个**，10–19 px 只有 2 个。它的对象全在 ≥20 px 区间。
所以 detailres 在 thrissur 上"掉了 0.015"不是反证，而是**这个事件根本没有对应尺度的目标可供改善**，只剩噪声。§3 里那个 1/2 同向的问题，本质是 dev 事件的事件选择问题，不是方法问题。

**(c) 1–4 px 目标在所有模型下都不可解。**
best 模型也只命中 77 个中的 8 个，像素召回 0.175。这个尺度的目标在 128 px 图块上只有 1–4 个像素，任何下采样 4 次的编码器都表示不出来。**这一档应当从优化目标里划掉，只作为报告项。**

**(d) DOFA 的差距有大半可以用 patch 尺寸解释，不能直接推广成"遥感预训练没用"。**
DOFA 是 ViT-B/**patch16**，输入 128 px → 特征图 **8×8 共 64 个 token**。一个 5–9 px 的滑坡不到一个 token 的一半。它在 5–9 px 档只召回了 2/75，在 ≥200 px 档 41/99 也明显低于 SegFormer 的 66/99——但后者说明的是**整体容量/收敛问题**，不只是分辨率。这条负结果目前是一个多因素混杂实验（编码器、预训练、解码器、40× 参数量、patch 粒度同时变），不能作为"Prithvi 类模型不值得试"的证据。M3 要做就必须把 patch 尺寸或输入分辨率对齐。

## 6. 对 M2 / M3 的具体修改

**M2（学习曲线）需要改三处：**

1. **判据从"best DEV"改成"固定步数 DEV"。** 建议主指标用 1,200 步读数，辅以平台均值（≥600 步）。`detailres_n075` 与 `detailres_n100` 这种 0.006 级的差，在 best 口径下永远说不清。
2. **池规模缩到 {559, 1113}，删掉 1671 和 2223。** 后两者已经被证明是平的，省下的 2/3 算力换 3 个种子（1234 / 42 / 777）。
3. **在 1,113 池上补一个"早停版"对照**：同样 3,600 上限但 `patience` 触发即停，用来量化"多花的 2,400 步"到底损失多少 DEV——这是给 M3 定预算的依据。

**M3（编码器对比）需要加两个前置约束：**

1. **输入分辨率或 patch 尺寸必须对齐。** 128 px + patch16 只有 64 token，任何 ViT 类模型都在这个设定下先天残废。要么把输入提到 256/512 并相应调整 bbox 采样，要么换 patch8 的权重。不解决这个，M3 只会重演 DOFA 的结论。
2. **必须先跑"随机初始化同容量 ViT"这个控制。** 否则"预训练有没有用"和"ViT 在这个分辨率上能不能用"混在一起，DOFA 这一批已经踩过一次。

**另外两条：**

- **给 dev 增加一个"小目标多"的事件。** 现在 253 个 ≤19 px 的 DEV 对象里 251 个来自 hiroshima，而 hiroshima 是 SEEN_DEV。任何影响小目标的改动，实际上都只在单个非盲事件上被评估。nepal / usa_alaska 虽然样本少，但作为**分箱召回**的补充事件比作为 IoU 事件更有价值。
- **FINAL（newzealand，338 块，32.5% 时相 fallback）现在不要动。** 配置还没定，任何一次查看都会永久污染这唯一的盲测。等 M2/M3 出了带种子的结论，再用固定配置跑一次。

## 7. 一句话给下一步

现在已经不是"再加数据"或"再换模型"能推进的阶段了：**TRAIN 0.49 / DEV 0.24 的落差说明瓶颈是泛化，5–49 px 的分箱说明瓶颈的物理位置是解码器细节分辨率，best 步数集中在 200–1200 说明瓶颈还包括预算与正则的配置。**
建议下一步只做一件事：**在 1,113 池上，用固定 1,200 步判据、3 个种子，把 detailres 与 standard 的差距定下来**。差距确认了，再谈 M3 的编码器；差距没确认，M3 换什么编码器都没有可信的基线可比。

## 8. 局限（写进任何引用这段结论的地方）

1. **全部是单种子。** 所有 Δ 的置信区间是"图块抽样"区间，因图块在事件内高度相关，实际区间比这里宽；事件级有效样本量只有 2。
2. **DEV 同时是选择集。** best 口径的数字系统性偏高 0.01–0.07，只有固定步数读数或 FINAL 才是无偏的。
3. **hiroshima 是 SEEN_DEV**，不是盲测；它的绝对数值不可与文献基线横比。
4. **thrissur 只覆盖 ≥20 px 目标**，不能用于任何小目标相关的判断。
5. 本次审阅**没有重跑推理**，所有数字来自已有 `per_tile_best_val.csv` / `objects_best_val.json`；如果当时的预测文件本身有问题，这里查不出来。
