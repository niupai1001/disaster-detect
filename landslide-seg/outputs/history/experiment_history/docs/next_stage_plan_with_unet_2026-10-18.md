### 仍需处理的工程与数据风险

1. `evaluate_segformer.py` 默认仍调用旧指标，metric v2 由独立 `revaluate_metric_v2.py` 运行。新模型若直接复用旧入口，会再次混淆口径。应统一模型无关的评测入口，显式保存 `metric_version` 和 cohort 身份。
2. `load_checkpoint()` 仍直接构建 `SegFormerSeg`；增加 U-Net 需要一个小型模型工厂，旧 checkpoint 缺少 architecture 字段时默认按 SegFormer 加载，保持兼容。
3. `max_steps` 仍在 epoch 后判断，resume 的 global_step 从 0 起算，last 保存早于 best 元数据更新。这些需要在下一轮按步数比较前修复并验证。
4. “最晚事件后选图”只是保守时间规则，不能保证所有早期对象当期仍可见；对象—ann_id—日期映射未完成。不得把 v3 命名为人工核实真值集。
5. 报告仍残留“tiny 基本不可解”“参考上限”“排除了实现回归”等过强表述，应改为数据支持的有限结论，并明确哪些表属于 v1、哪些属于 metric v2/v3。

## 2. U-Net 对照的定义

### U0：一组必要的主对照

| 项目   | 计划                                                   |
| ---- | ---------------------------------------------------- |
| 成熟实现 | `segmentation_models_pytorch.Unet`，锁定现有 0.5.0        |
| 编码器  | ResNet18，ImageNet 预训练，全部可训练                          |
| 解码器  | SMP 标准 U-Net 解码器及跳跃连接；随机初始化，正常训练                     |
| 输入   | 与 SegFormer 完全相同的 10 波段、128×128 网格                   |
| 首层   | 先加载三通道预训练，再显式扩为 10 通道                                |
| 初始化  | R/G/B 权重复制到 B04/B03/B02；其余 7 通道置零且可训练；与 A0 的策略一致     |
| 输出   | `[B,1,H,W]` 原始 logits，`classes=1, activation=None`   |
| 附加模块 | 不加 Spectral Stem、注意力、语义模块或额外分类头                      |
| 主要比较 | U0 vs A0：同 direct10 的基线比较；U0 vs A1/B1：完整候选方案的效果与成本比较 |

这是 **ResNet18 编码器的 U-Net**，不要在论文中写成逐层复现最初的原版 U-Net。选择它是为了使用成熟实现和已有预训练，减少自制网络的实现风险。[SMP 官方文档](https://smp.readthedocs.io/en/latest/models.html)与[官方仓库](https://github.com/qubvel-org/segmentation_models.pytorch)提供该模型及预训练编码器接口。

不能只传 `in_channels=10` 就默认与 A0 初始化一致：SMP 有自己的多通道适配规则，应显式复制 RGB、清零其余波段，并验证输出与 RGB 选择输入的等价性。三通道权重来源、revision/文件 SHA、加载键、首层替换和参数组都要记录；加载失败必须报错，不可静默回退到随机初始化。

首轮只新增 U0，一共五个模型组。若后来需要区分“U-Net 架构”与“投影输入”效应，再增加 10→3 投影的 U1，作为后续机制对照，不在本轮扩大矩阵。

### 公平性边界

- 现有 SegFormer 使用 ADE20K 分割预训练的编码器及解码器，U0 计划只使用 ImageNet 预训练编码器。初始任务经验不同，主实验只能比较这两个实际迁移方案，不能纯粹证明 CNN 比 Transformer 更好或更差。
- 本轮实际构建的 10 通道 U0 有 **14,350,161** 参数，约为 A1（3,753,602）的 3.82 倍。不能称为参数量匹配对照，也不能预先称 U-Net 更轻量。
- 同步数不等于同计算量；同时报告 GPU 时长、参数量、峰值显存、batch=1 的同步推理 p50/p95，以及批量吞吐。
- U-Net 的最终全分辨率输出、跳跃连接不等于所有编码特征都保留原始网格细节；不能预先保证 tiny 或边界会更好。
- 若后续研究需要纯架构归因，应另设相近预训练来源和随机解码器的受控实验。不要为了加入 U0 就丢弃现有 ADE 基线。

## 3. 第一轮五组公共协议

| 组别 | 网络               | 输入         | Spectral Stem |
| -- | ---------------- | ---------- | ------------- |
| A0 | SegFormer MiT-B0 | direct10   | 关闭            |
| A1 | SegFormer MiT-B0 | direct10   | 开启            |
| B0 | SegFormer MiT-B0 | 10→3 可学习投影 | 关闭            |
| B1 | SegFormer MiT-B0 | 10→3 可学习投影 | 开启            |
| U0 | ResNet18 U-Net   | direct10   | 关闭            |

第一轮冻结 `s2_10band_v3_p20`，不要同时改变采样、损失、时相规则和增强。复用 train 1,480 / Hiroshima 448 / Italy 2,795，训练集统计做 10 波段 z-score，不另对 U-Net 叠加 ImageNet 归一化。验证/测试无随机增强。

公共项：

- masked `0.5 BCEWithLogits + 0.5 Dice`；现有翻转/90°旋转增强；阈值 0.5。
- AdamW、现有 wd/warmup/poly/梯度裁剪规则；编码器 6e-5、解码器和新头 6e-4。U0 扩展首层属于编码器，首轮与 A0 保持同一 LR 规则。
- FP32，batch 64，**3,600 次更新**，三个种子 1234/2026/3407；验证频率与 v3 一致，每 24 次更新一次，按 Hiroshima 前景 IoU 选择 best。
- 只在验证数据上选择超参/阈值；主结果维持 0.5，阈值扫描另列。对测试集不做面积过滤或选择性后处理。
- 数据顺序和增强随机流与模型初始化独立；记录实际参数组、训练模式、BatchNorm 行为和有效 batch。
- 先确认 U0 在共同设备上能以 batch64/FP32 运行。若不满足，不能偷偷换更小 batch 或认为梯度累积等同 BatchNorm 的真实 batch；应明确资源限制，或定义新的公共协议并对五组一致重跑。

已有四组 v3 运行通过配置/指标/数据身份核对即可复用，首轮只需新增 U0 的三次正式训练；若公共协议有实质改变，则不能与旧结果拼成“同协议五组”，需要重跑受影响对照。

相同 LR 是受控的第一轮起点，不保证每种架构的最佳训练条件。若 U0 训练不足或不稳定，先检查权重和梯度，再为 U0 与 A1/B1 分配对称、有限的验证集调参预算，单列“同协议”与“等调参预算”结果。

## 4. 执行顺序与验收

### P0：统一实验入口与身份记录

保留旧结果；统一 metric v2 和固定 cohort；增加模型 factory，输出统一为 `{'logits': ...}`，让损失、valid、可视化和性能统计继续复用。checkpoint 保存 architecture/backbone/adapter、预训练身份及数据/统计/指标版本，旧 SegFormer checkpoint 继续可加载。

修复 step 停止与 resume：测试在非 epoch 整倍数的预算停止，校验恢复后的累计步数、优化器/调度器、best 元数据、数据顺序与增强状态。若支持中途恢复，必须保存 batch 位置或明确只支持 epoch 边界恢复。

验收：已有 checkpoint 重载输出不变；同一概率输入在两个模型入口得到一致指标；无效像素不影响损失/评测；不会把随机权重标记为预训练。

### P1：U0 接入与训练前验证

加载并核验 ResNet18 预训练，扩首层并检查 RGB 映射；真实 batch 前向、反传、参数更新、保存重载。再选取可观察性较好的训练样本进行 8–16 张过拟合检查，绘制损失和预测。

过拟合验收应关注有效区域内损失持续下降、各组件实际更新、可视化对应关系及重载一致性，不使用随机初始化图作为效果。若不能拟合这些样本，暂停正式训练定位接口/监督问题。

### P2：完成 U0 三种子，形成五组主结果

产出 pixel IoU/Dice/P/R、small/medium/large 与 tiny 的对象召回和分子分母、边界 F1、背景像素 FPR；可靠独立负瓦片不足时，瓦片误报率为 N/A。保存 train/val 曲线、best/last、配置、权重身份和效率指标。

除 Hiroshima 外，分别报告固定的 Italy 三个 cohort。继续复用 batch1 的 30 张历史案例，加入 v3 新区域中按预设规则选择的失败/成功样本；不为每个模型只挑各自最好样本。报告地区、对象尺度、可观察性、截断状态和错误类型。

若 U0 在像素 IoU、边界/小对象召回和误报之间存在取舍，按这些指标分别讨论；不能只用单一总体 IoU 宣布胜者。若 U0 已接近或超过复杂方案，应先确立强基线，再讨论附加模块价值。

### P3：把“扩量”和“更多更新”分开

现有共同子集复核已经完成。下一步在开发验证协议预注册后，以 A1 为首个诊断模型做：

| 数据                   | 3,000 steps | 3,600 steps |
| -------------------- | ----------- | ----------- |
| v2_clean train 1,237 | 已有          | 待补          |
| v3_p20 train 1,480   | 待补          | 已有          |

补足两个条件即可形成数据×预算的 2×2 比较。调度总步数随该条件改变，必须完整记录；它比较的是预注册训练预算方案。检查旧实验的验证频率差异，统一可比较的 checkpoint 选择规则，不能因为验证次数更多而额外获得选优机会。必要时重跑这个小矩阵，而非拼接不一致结果。

若发现明确数据收益，再用 U0 验证是否跨架构成立。新增数据统计量使用对应训练集拟合并记录；如需单独解释归一化影响，再加固定旧统计量对照，不先扩展成大规模网格搜索。

### P4：定向数据扩充与验证设计

现在训练规模增幅有限，新增测试文件不贡献训练监督。下一轮优先补独立训练事件、农田/丘陵的小型滑坡、细长对象，以及经核实的建筑、道路、裸地等困难背景。未标注数据只进入待核查池。

继续审核多日期对象、超长观测间隔和 SCL/标签可观察性，规则不依赖模型预测优劣。更晚于最晚事件不保证所有历史滑坡仍可见；无法核实的对象保留不确定性记录或进入独立隔离集合。

为泛化研究新增多个开发验证事件/区域，按事件与空间邻接分组；设立未参与选择的新最终留出事件。训练样本的多期观测和邻接裁块不能跨 split 泄漏。新验证协议意味着新实验版本，五组应共享该版本；历史 Hiroshima/Italy 继续保留为诊断集。

T2 的事件/尺度均衡采样放到这一阶段再复测，预设上限，兼顾困难背景；不要把弱正向结果直接固化为全部模型默认。T1 暂保留原 LR；更强光谱增强、边界损失和分支调整都排在数据、对照和验证协议之后。
