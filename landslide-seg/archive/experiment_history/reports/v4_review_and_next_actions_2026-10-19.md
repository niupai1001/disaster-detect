## 3. 必须修正的问题

### P1：归一化包含新协议的 DEV / FINAL

`configs/segformer/v4/base.yaml` 引用 `data/s2_10band_v4_p20/stats.json`；后者 `fit_split=train`、`n_samples=2805`。`build_s2_10band_v2_clean.py:249–250` 按基础清单的旧 split 生成统计，随后新协议重划分并没有重新拟合统计。

真实拟合集合为：

| 新协议角色 | 图块数 |
|---|---:|
| 合法 TRAIN | 2,223 |
| FINAL newzealand | 338 |
| DEV thrissur | 221 |
| EXCLUDE nepal + usa_alaska | 23 |
| 合计 | 2,805 |

独立像素复算精确匹配，证实不是统计文件中的过期样本数描述。这属于预处理利用目标事件影像分布，虽然不是标签泄漏，仍不符合目标事件不可见的 strict OOD。

**修复**：新建统计文件和协议修订目录，保留旧文件供旧 checkpoint 复现。主学习曲线建议只用共同的 25% 训练核心 559 块拟合一次，四档共享，既不读取 DEV/FINAL，又避免随 N 改变归一化。把它明确命名为“固定预处理下增加监督训练样本”的实验。若采用全体 2,223 个合法训练图像拟合并共享，也必须声明小档使用了训练候选池额外未监督图像的统计，不能称纯粹仅看 N 张影像。二者选定一种后保持不变，不扩成额外矩阵。

生成时保存拟合 sample_id、事件、像素数、波段、来源清单哈希和统计文件哈希。训练启动验证拟合集合与 DEV/FINAL 无交集。评测也检查统计哈希，不能覆盖旧 stats 后再评旧 checkpoint。

### P1：固定 3,600 步没有真正实现

`segformer_trainer.py:473–475` 仅将 max_steps 用于 scheduler 总步数；外层 `:552` 仍限定 epochs=150，`:597` 只在完整 epoch 结束时判断退出；`_train_epoch` 内没有剩余步数限制。

| 训练档 | 每 epoch 更新数 | 当前控制流程执行数 | 目标 |
|---|---:|---:|---:|
| 25% | 9 | **1,350** | 3,600 |
| 50% | 18 | **2,700** | 3,600 |
| 75% | 27 | **3,618** | 3,600 |
| 100% | 35 | **3,605** | 3,600 |

表内结果来自实际控制函数的桩执行，假定没有全 ignore batch 跳过。前两档不仅少训练，学习率也按 3,600 步衰减、提前结束，将严重混淆数据量效应。仅把 epochs 改大仍不能解决整 epoch 超跑。

**修复**：以成功 optimizer update 为终止条件；在 batch 内精确截断；以更新数驱动 scheduler、验证、保存；max_steps 模式自动允许足够遍历，epochs 不再静默截短。恢复训练须还原 global_step、batch 游标和采样状态，目前 resume 将 global_step 重新置零也不满足此要求。

同时明确 batch 规则：目前 drop_last=False，尾批大小分别是47/25/7/47，固定 steps 不等于固定总样本曝光。建议使用可跨 epoch 接续的确定性 shuffle 样本流组成完整 batch64，记录实际曝光量与独立覆盖数；不因预算修复额外增加复杂采样策略。

### P1：双 DEV 尚未进入 checkpoint 选择

`make_pool_manifests.py:66` 将 val 写死为 Hiroshima；四档实际均为 val448。Thrissur 被放到单独 test 清单，只做训练后评估。训练器只算单一 pooled IoU，因此尚未实现“多个开发事件共同选择”。

**修复**：DEV 清单同时纳入 Hiroshima448 和 Thrissur221。预先固定以二者**事件等权平均 IoU**选择 checkpoint，并记录两事件分别的 TP/FP/FN 与 IoU；pooled IoU 作补充，不代替事件均值。每100个成功更新验证一次（四档统一36次），避免按 epoch 验证导致不同 N 的选择机会不同。Hiroshima 仍是有效的开发事件，历史参与调参使它不能当盲测，并不意味着它的事件外验证信息完全无效。

### P1：FINAL 的实际使用与声明冲突

报告 §5.3 已公开 New Zealand 冒烟 IoU 0.1376；§9 要求每档评 FINAL，§8/§9 又以 FINAL 与 DEV 的方向关系指导下一步。加上它已经进入统计拟合，不能再称“真正从未被看过、干净的 FINAL”。

一次冒烟看分数本身并不证明实际发生了模型选择；但继续按该方案反复据 FINAL 决策，会明确将其转成开发数据。

**修复**：如实记录已查看及统计拟合的历史，保留现有事件划分，不通过换一个已用事件来制造“盲测”。修正统计后，将 New Zealand 保留为**已查看历史、后续冻结评估集**。后续开发阶段不自动评它；仅在研究决策和模型配置冻结后统一评预先指定模型。若需要真正从未接触的外部测试，另找新事件，作为后续研究要求，不阻塞本次学习曲线。Italy 也不得用于选择阈值、架构和后续路线。

### P2：冻结目前是说明字段，未绑定完整运行输入

`build_v4_protocol.py:156–158` 的 hash 覆盖事件设计/计数/汇总，不包含每个成员的完整身份、缓存或统计哈希；重跑可直接覆盖 frozen 文件。`make_pool_manifests.py` 读取 hash 但没有验证数据版本、候选池成员、冻结状态与哈希的一致性。训练器只校验所传 manifest，不验证它是否符合 OOD_V4。

**修复**：增加轻量启动契约校验，绑定 split、实际成员、stats、权重和配置哈希；拒绝未知/重复成员、角色错配和跨集合交集；已有冻结版本不可静默覆盖，使用新修订。基础 base.yaml 默认指向旧角色清单，不能作为可直接正式运行的最终配置，生成每个实验独立配置或启动时强制指定派生清单。

### P2：当前日志不足以回答计划中的机制问题

训练日志有 train_loss、val IoU，但没有干净推理模式下的 train IoU；当前评测入口没有实现计划要求的像素 AP，也未覆盖全部 1–4/5–9/10–19/20–49/50–199/≥200 px 分档。指标单测通过不能替代未实现的指标。

**修复**：至少保存 best 与 final-step checkpoint 在本档全部训练样本上的无增强指标；另给共同训练候选池参考指标，但小档未见过其余样本，因此该参考指标不能标成其“训练拟合能力”。保存每事件 pooled 混淆计数、AP、对象各档召回、边界 F1 和预测量。负样本仍未独立核实，负影像误报率维持 N/A，不把未标注图块当负样本。先补这些诊断，再依据 train/DEV 分离判断机制。

## 4. 报告文字与方法论修订

1. “前景交集为0时 IoU 未定义”应改为“**并集为0**时未定义”。交集0但并集>0时 IoU=0；本轮通过的测试实现对此是正确的，错误在说明文字。评测 CSV 又将 None 用 `or 0.0` 转成0，后续导表应保留空值，避免与 JSON 口径不一致。
2. DN落在[0,10000]只能支持值域合理，不能单凭值域证明数据来源为 harmonized；需靠已有下载来源/档案哈希。无需为了证明现有来源再下载 raw。全局 z-score 也不能普遍消除仅部分日期含有的+1000偏移，相关代码/统计说明应更正。
3. “新增数据全部来自新事件”不准确，kyrgyzstan1 本来已有277个 nc，扩量同时来自旧事件补齐和新事件。
4. 前景像素占比略低，不能推出“极小目标更少”，需看对象面积分布。审计45个 nc通过，不能推出全部样本标签可见。时间在最晚事件之后是必要检查之一，不是标签可观测性的充分证明。
5. 只有一个 FINAL 事件，无法估计跨事件不确定性；338图块及fallback比例不足以推算“标准差必然很大”。不应对空间相关图块按独立样本 bootstrap 后称事件泛化置信区间。
6. 固定3,600步曲线在50%平台，只能说“在这份划分、预处理与更新预算下暂未观察到收益”，不能排除数据量作用。大档曝光次数更少，优化轨迹、样本构成和事件覆盖均可能影响结果。暂不恢复完整双预算矩阵；只有曲线明显未收敛时，按预定规则补一个端点诊断。
7. 原计划三seed条款与此前明确的单seed要求不同；本轮行动按 **seed1234**。不自动扩到三seed，不报告显著性或跨seed稳定性。三seed可在以后形成正式研究结论时另行考虑。
8. 原计划多编码器首批是 B0/B2/DOFA，初始报告扩大到 Prithvi、TerraMind、AnySat，没有必要现在同时启动。B0+Stem与B2无Stem也不是纯容量对照，比较容量时应保持同一Stem设定。
9. Prithvi以30m HLS六波段预训练，不等于所有下游输入必须降到30m。官方模型卡还报告跨分辨率下游任务。应先核对官方适配接口、Narrow-NIR对应B8A与单位归一化；不应先验损失小目标细节。若有意测试30m，需建立独立分辨率对照，不能只给Prithvi降采样再与10m SegFormer排名。
10. 当前SegFormer冒烟参数摘要为 total=trainable=**3,753,602**。主干、解码器、输入适配权重、Stem与融合头均设为可训练；这条主线没有大量冻结参数。TerraMind/AnySat/TiM/复杂语义和粗定位未进入本轮主训练配置。是否每层实际获得梯度由后续最小梯度检查确认，requires_grad统计不替代梯度检查。

### 第三步：用最少分支回答机制问题

只依据TRAIN和两个DEV决定后续，不依据FINAL。

| 已得到的证据 | 下一项最小实验 | 结论边界 |
|---|---|---|
| 两DEV与小目标召回总体随N改善，末端仍上升 | 近似固定N的少事件/多事件对照；盘点合法外部训练事件 | 支持覆盖/样本量有作用，不证明它是唯一瓶颈 |
| Train高、两DEV明显低或走势相反 | 按事件留一的开发诊断，检查背景捷径和事件权重；再考虑多光谱预训练 | 泛化不足，不直接归因为某一种域偏移 |
| Train也低且更新末端仍明显改善 | 一个受控预算/优化端点诊断，结合既有过拟合结果与少量定点案例 | 不将低train自动当容量不足 |
| 控制工程与优化后数据收益有限 | B0/B2同Stem设定的容量对照 + DOFA官方实现的表征对照 | B2差异包含容量与预训练层级；DOFA全系统差异不能全部归因编码器 |
| 多个编码器都在相同对象上失败 | 固定样例的单期可观测性审核；必要时官方单期/多时相+DEM独立协议 | 用于诊断输入信息上限，不改变单期主任务 |

冻结probe时所有候选使用可比较的head和输入条件，记录原生stride、投影参数和归一化；完整微调保留各官方成熟组件，明确这是系统比较。Prithvi/TerraMind/AnySat推迟，不与第一批构成大规模笛卡儿积。

不把人工可见性全量审核、raw下载、官方整套复现当作本次六组训练的前置门槛。仅在具体失败机制需要时，抽查对应案例并记录未知，不按模型预测反推标签错。
