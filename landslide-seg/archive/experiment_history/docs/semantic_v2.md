# 语义设计 v2：类别概念 + 影像条件属性 + 关系对比

> 本文档替换 v1 的语义实现。v1 已判定为**设计错误**，保留代码仅用于 `ClassOnly` 对照组。

---

## 1. v1 错在哪里（有实测证据）

| 问题 | v1 的做法 | 后果 |
|---|---|---|
| 没有影像条件化 | 一条固定英文短语 → 固定 512 维向量，**每张图完全相同** | 语义分支只提供一个常数锚点，样本间无差异 |
| 属性不可用 | 算了 5 条属性向量，但**从未被任何代码读取**，`L_attribute` 恒为 0 | 死代码，却被文档写成"属性语义" |
| 没有关系语义 | 只有整图相似度 | 无法表达"候选区与周边背景的对比" |
| 判别力弱 | RemoteCLIP 文本空间基线相似度 0.6–0.85，"滑坡 vs 猫"=0.62 | 先验信息量极低 |
| 语义占满粗 logits | 初始化时语义项占粗 logits 变化的 **99.6%**（FPN 原始幅度仅 0.0036） | 粗定位其实是在看语义图，不是在学影像 |

## 2. v2 结构

```
                         ┌── 类别语义：class_query (文本编码, 冻结, [1,512])
                         │
P0 [B,128,128,128] ──1×1──► vis [B,512,128,128] ──┐
                         │                        │
   整图池化(valid) ──► attr_head ──► attr_logits [B,K]
                         │              │
                         │              └─ σ(·) ──► α [B,K]
                         │                          │
                         │        Σ α_k · attr_emb[k]  （属性词向量, 冻结 [K,512]）
                         │                          │
   候选区 soft mask ──► 关系特征 [B,141] ──rel_proj──┤
   （来自预测粗 logits）                            ▼
                                          dyn [B,512] = normalize(class + 属性 + 关系)
                                                    │
                              ┌─────────────────────┼─────────────────────┐
                              ▼                     ▼                     ▼
                    sem_map = cos(vis,dyn)·10   FiLM(γ,β)          区域嵌入(对齐用)
```

### 2.1 三层语义

| 层次 | 实现 | 是否随样本变化 |
|---|---|---|
| 类别语义 | `class_query`，冻结文本编码 | ❌ 稳定（设计如此） |
| 属性语义 | `attr_head`：`[B,128] → [B,K]` 响应 → 加权组合属性词向量 | ✅ **由影像决定** |
| 关系语义 | FG/BG 的视觉差(128) + 光谱差(10) + 纹理差(1) + 面积/离散度(2) | ✅ 由预测候选区域决定 |

### 2.2 关键约束（已写进代码）

- 关系特征用的是 `region_soft = sigmoid(粗 logits)`，即**预测**的候选区域，**不是 GT**。
  因此训练与推理走同一条路径，不存在 teacher-forcing 错配。
- 顺序是"两遍"：先 FPN 出粗 logits → 再算属性/关系 → 语义回补到粗 logits。
  避免"语义依赖候选区、候选区依赖语义"的循环。
- 语义相似度是**真正的余弦**（视觉侧也归一化），量级不随通道方差漂移。

## 3. 属性词表（只放 10 m 能看见的）

| 键 | 文本 | 判读要点（10 m） |
|---|---|---|
| `exposed_soil` | exposed soil on a slope | 裸土色块，与周围植被边界清晰 |
| `rocky_scar` | rocky landslide scar | 灰白/亮色岩质后壁，常有阴影 |
| `veg_disturbance` | disturbed or broken vegetation | 植被纹理断裂、颜色不均但未完全裸露 |
| `debris_texture` | debris flow texture with mixed deposits | 条带状/舌状堆积，内部斑驳 |
| `water_wet_ground` | standing water or wet ground | 深色、低 SWIR 反射 |
| `dense_forest` | dense forest canopy | 高 NDVI、纹理均匀 |
| `sparse_vegetation` | sparse vegetation or shrubland | 中 NDVI、纹理较碎 |
| `bare_rock` | bare rock or cliff | 高亮、无植被、常伴阴影 |
| `cropland_flat` | cropland or flat field | 规则几何纹理 |
| `shadow_or_cloud` | terrain shadow or cloud | 需与真实地物区分，仅作质量提示 |

**明确排除（10 m 不可辨认，禁止写入标签）**：
`lithology`、`slip_surface_depth`、`building_floors`、`soil_moisture_pct`。

## 4. 标注协议

### 4.1 三值语义

| 值 | 含义 | 是否参与损失 |
|---|---|---|
| `1` | 该属性**可辨认地存在** | ✅ 正例 |
| `0` | 该属性**可辨认地不存在** | ✅ 负例 |
| 缺省（不写） | **未知**：被云遮挡、分辨率不足、无法判断 | ❌ **完全排除**，绝不当负例 |

代码里以 `-1` 表示未知；`attribute_loss()` 只对 `target >= 0` 的项计算 BCE。

### 4.2 标注单位

- **区域级**：以候选滑坡区（GT 掩膜的连通域）为单位，标注该区域的属性；
- **图级**：以整图背景为单位，标注背景类型（`dense_forest` 等）。
- 两者共用同一词表；一个区域可以同时有多个属性为 1（如"裸土 + 碎屑纹理"）。

### 4.3 文件格式

`labels/attributes.jsonl`，每行一个样本：

```json
{
  "sample_id": "italy_s2_1592",
  "image_level": {"dense_forest": 1, "cropland_flat": 0},
  "regions": [
    {"region_id": 0, "bbox": [12, 30, 40, 55],
     "attributes": {"exposed_soil": 1, "debris_texture": 1, "veg_disturbance": 0}}
  ],
  "annotator": "A",
  "confidence": "high",
  "notes": "区域内有薄云，边界不确定"
}
```

### 4.4 最小可靠批次（下一步要做的）

| 项 | 计划 |
|---|---|
| 样本量 | 3 个事件 × 12 个正样本 = **36 个**（先做小批） |
| 标注人 | 2 人独立标注同一批，计算逐属性 Cohen's κ |
| 接受门槛 | κ ≥ 0.6 的属性才进入训练；低于门槛的属性降级为"未知" |
| 复核 | 第三人仲裁分歧项 |
| 负面样本 | 本数据集无已验证负样本，图级负例暂缺（见 blockers B6） |

## 5. 消融矩阵（已可一键运行）

| 名称 | 配置 | 检验什么 |
|---|---|---|
| **ClassOnly** | `model.semantic.mode=class_only` | 基础语义对照（等价 v1） |
| **FULL** | 默认配置 | 类别 + 属性 + 关系，三阶段全开 |
| **−SemAlign** | `ablation.sem_align=false` | 去掉区域-文本对比 |
| **−SemLoc** | `ablation.sem_loc=false` | 去掉语义对粗 logits 的注入 |
| **−SemRef** | `ablation.sem_ref=false` | 去掉语义图与 FiLM 对细化器的作用 |
| **−Attributes** | `model.semantic.use_attributes=false` | 去掉属性组合（只剩类别 + 关系） |
| **−Relation** | `model.semantic.use_relation=false` | 去掉区域-背景关系 |
| **ShuffledAttributes** | 见下 | 打乱**有标注**的属性配对，检查模型是否真的在用对应关系 |

`ShuffledAttributes` 的做法：只打乱有可靠标注的样本之间的属性目标（同 batch 内置换），
不改变输入影像。若指标不下降，说明模型没有利用属性-区域的对应关系。

实测 7 种配置均能构建并前向（logits 均值各不相同），`−SemAlign` 时 `region_embedding` 为 `None`。

| 小批标注 | ⏳ 未开始（协议已就绪，见 §4.4） |

**因此现在能说的是**：动态语义的**推理路径**已接通（每张图产出不同的语义向量），
但"属性是否与真实区域对应"这件事**还没有被验证**——那需要 §4.4 的标注批次。
在拿到标注之前，`−Attributes` 与 `ShuffledAttributes` 两组消融没有意义。

## 7. 当前实测行为（2026-10-18，未训练权重）

4 个 test 样本（italy）直接前向，测动态语义的真实输出：

| 指标 | 实测 | 含义 |
|---|---|---|
| 属性响应 σ(attr) | 全部落在 **0.479–0.520** | 头是 bias 主导，输入贡献可忽略 |
| 属性响应跨样本标准差 | **0.000–0.001** | **当前并没有被影像激活** |
| `dyn` 两两余弦 | **0.993–0.999** | 每张图的语义向量几乎相同 |
| `dyn` 与 `class_query` 余弦 | 0.803–0.811 | dyn ≈ 类别查询 + 很小的扰动 |
| `relation` 范数 | 2.24（=√5，块归一化后） | 归一化生效 |
| `attr_head` 梯度范数 | **7.5e-6** | 太弱 |
| `rel_proj` 梯度范数 | 3.0e-4 | 比属性头强 40 倍 |

**结论（必须说清楚）**：结构按设计接通了，但**当前语义仍然是"类别查询 + 近似常数的属性/关系项"**，
并没有实现"每张图不同"的效果。原因有三，按重要性排序：

1. **没有属性标注** → `attr_head` 只能收到分割损失的间接梯度（7.5e-6），
   而 bias 主导输出，所以恒为 0.5；
2. 即使有梯度，属性头的梯度比关系头弱 40 倍（因为 α 要经过归一化再进 dyn）；
3. `dyn` 经过 L2 归一化后，幅度差异被抹掉，只剩方向差异，而方向又被类别查询主导。

**这不是"实现错了"，是"还没被训练/监督"**。要使它真正成立，必须：
- 先做 §4.4 的小批属性标注（36 个样本），让 `L_attribute` 生效；
- 训练后重新测"属性响应跨样本标准差"是否显著大于 0（阈值可设 0.05）；
- 再跑 `ShuffledAttributes`：如果打乱属性配对后指标不掉，说明模型没用上对应关系。

在完成这三步之前，任何"语义带来了什么"的说法都不成立。
