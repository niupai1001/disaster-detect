# DEM 的作用与外部数据集结构核对（2026-10-20）

## 一、Sen12Landslides 的 DEM 到底是什么

读本地 nc 与官方代码得到的硬事实：

| 事实 | 证据 |
|---|---|
| DEM 是**静态层**，不随时间变 | `DEM` 形状 `(15,128,128)`，但 15 个时相两两 **完全相同**，沿 time 方差 = 0 |
| DEM 没有日期属性 | 文件全局属性只有 `ann_id / ann_bbox / event_date / date_confidence / pre_post_dates / annotated / satellite / center_lat / center_lon / crs`；`DEM.attrs` 只有 `grid_mapping` |
| 官方怎么用 | `datasets.py`：取 `time=0` → 转置 `(y,x)` → **广播到全部 T 个时相** → 与十波段拼成 11 通道 |
| 量纲 | int16，整数米（hiroshima 样例 109–432 m），10 m 重采样，块内高程极差中位数 294 m |

因为是静态层且无日期，**"灾前还是灾后"在产品里无法判定**；它与影像的时相差也不构成"几天"的问题——
它根本不是一个时相，而是被复制了 15 份的一张底图。所以你的判断是对的：**滑坡区的 DEM 与该区域高程是连续的，
它不含任何事件信息**。

## 二、那它凭什么可能有帮助？——实测

在官方 TRAIN 抽 500 块（819 万像素，滑坡占 3.84%）：

### 2.1 高程本身几乎无判别力

| DEM 区间 | 滑坡像素占比 | 相对基准 |
|---|---:|---:|
| 0–100 m | 0.0216 | 0.56× |
| 100–300 m | 0.0496 | 1.29× |
| 300–600 m | 0.0380 | 0.99× |
| 1000–1500 m | 0.0371 | 0.96× |
| 2000 m 以上 | 0.0193 | 0.50× |

**单变量 AUC = 0.46**，即比随机还差一点。频率只在 0.5×–1.3× 基准之间浮动。

### 2.2 有价值的是它的导数（坡度），不是高程

| 变量 | 单变量 AUC |
|---|---:|
| 高程 | 0.46 |
| **坡度（由 DEM 求梯度）** | **0.6127** |

坡度分档的滑坡占比：

| 坡度 | 滑坡占比 | 相对基准 |
|---|---:|---:|
| 0–5° | 0.023 | 0.6× |
| 10–20° | 0.026 | 0.7× |
| 25–30° | 0.039 | 1.0× |
| 30–40° | 0.050 | 1.3× |
| **40° 以上** | **0.078** | **2.0×** |

**结论**：DEM 能"被利用"不是因为高程本身，而是因为它可以导出坡度/起伏，而坡度与滑坡发生有中等相关。
但即使是坡度，AUC 只有 0.61，属于**弱先验**——它只能调"哪里更可能塌"，不能告诉你"这里塌了"。
直接喂原始高程，模型要自己学会求梯度，效果大概率不如显式给坡度。

这也解释了 Landslide4Sense 为什么同时给 **B13 坡度** 和 **B14 高程** 两个通道。

## 三、Landslide4Sense 的结构（已核实到代码）

| 项 | L4S | 本项目 |
|---|---|---|
| 容器 | 每块一个 `.h5`：`image_N.h5` / `mask_N.h5` | 每块一个 `.npz` |
| 键名 | 图像 `hf['img']`，掩膜 `hf['mask']` | `x10` / `mask` / `valid` |
| 图像形状 | `(128,128,14)` → 转置成 `(14,128,128)` | `(10,128,128)`（单期） |
| 掩膜 | `(128,128)` float32，{0,1} | `(128,128)` uint8，{0,1} |
| 波段 | S2 **B1–B12（缺 B8A）** + ALOS 坡度 + ALOS DEM | S2 **B02–B12 含 B8A**，无 B1/B9/B10 |
| 时相 | 无（单期） | 15 个（本项目取单期） |
| valid | **没有** | 由 SCL 推导 |
| 归一化 | 存储时已标准化（mean≈0、std≈1），加载时再套固定 mean/std | 存原始 DN（int16），训练时按 TRAIN 统计做 z-score |
| 元信息 | 文件内不含日期/坐标（官方刻意不公开） | 有 `event_date`、`pre_post_dates`、中心坐标 |
| 划分 | 按图块随机（train 3799 / val 245 / test 800），测试集无标签 | 本项目为事件级互斥 |

**可直接衔接的部分**：128×128、10 m、二值前景掩膜 —— 这三条一致。

**不能直接衔接的部分**（按麻烦程度）：

1. **B8A 缺失**：L4S 用 B1–B12，明确说明"原始采集时省略了 B8A"。我们的第 8 通道就是 B8A。
   要么少一个波段，要么用 B8 或 B11 替代，都会改变输入定义。
2. **多了 B1/B9/B10**（60 m 上采样到 10 m），这三条我们没用。
3. **多了坡度与 DEM 两个通道**，其中坡度恰恰是最有用的那个（见 §2.2）。
4. **没有 valid 掩膜**：我们是按 SCL 排除无效像素和云；换过去要么接受全像素计算，要么自己造 valid。
5. **归一化口径不同**：L4S 存的已是标准化值，要与我们混合必须先反标准化再按统一统计重算。
6. **没有日期**：无法做我们的"灾后单期选择"，只能按官方给的那一期用。

## 四、MS2LandsNet 的说明（需要更正一处）

**MS2LandsNet 是一个轻量分割网络的名字**（Int. J. Digital Earth, 2023），不是数据集。
那篇论文自建的数据集叫 **Luding（泸定）** 和 **Jiuzhaigou（九寨沟）**，另加 Landslide4Sense 做对比。
PLOS ONE 2026 那篇把它写成"MS2LandsNet Dataset"，属于二手引用里的误用，容易被误导。

已核实：数据为 Sentinel-2 中分辨率（10 m）多时相，覆盖泸定/九寨沟一带，配二值掩膜；
论文给出的是 **Google Drive 上的数据获取与预处理代码**，不是打包好的数据集文件。
**具体文件格式我没有核实**（未拿到样本），要确认需先按其 Drive 代码跑一遍。
