## 1. 先回答："拉全分卷"是什么意思

Sen12Landslides 的 Sentinel-2 部分在 HuggingFace 上**不是一个大文件**，而是按顺序切成
**28 个压缩包**：

```
data_harmonized/s2/s2_part01.tar.gz  ~1.41 GB
data_harmonized/s2/s2_part02.tar.gz  ~1.39 GB
...
s2_part28.tar.gz                     合计 ≈ 39 GB
```

每个包里装着若干 `*_s2_*.nc`（每块 128×128×15 时相，约 3 MB），官方统计共 **13,628 个 S2 样本**。
分卷是按事件名排序的，所以相邻分卷往往还是同一个事件：

| 分卷 | 事件 |
|---|---|
| part01 | chimanimani（续） |
| part05 | dominicamaria → hiroshima |
| part10 | italy |
| … | 其余事件 |

**我们目前只下了 part01 / part05 / part10 = 1,500 个 `.nc`，覆盖 4 个事件。**
"拉全分卷"就是把 part02–part04、part06–part09、part11–part28 全部下载并解压，
拿到 13,628 个样本、全部事件，才能做"多事件训练 + 事件互斥测试"。

代价：≈39 GB 下载 + ≈40 GB 解压（N 盘当前剩 2.67 TB，够用），耗时按实测带宽约 20–40 分钟。

## 2. 训练管线：从磁盘到 loss

```
manifests/certified.jsonl          ← 认证清单（72 条，含 cache 路径与哈希）
        │  verify_cache(): 校验每个 npz 的 SHA-256 前 16 位
        ▼
data/certified/<sample_id>.npz     ← x12[12,128,128] x10[10,128,128] mask[128,128] valid[128,128] doy
        │  make_batches(): 按 split 取样、可选 shuffle、校验哈希、mask<0 置无效
        ▼
ModelBatch (x12, x10, s2_dates, mask, valid, sample_ids, provenance)
        │
        ├─► TerraMind 支路：normalize_s2l2a_dn → [B,12,128,128] → 双线性到 224×224
        │        → terraMind_v1_small_tim（冻结）→ 4 层 token [B,196,384]
        │        → 末层 reshape [B,384,14,14]，物理 stride ≈ 91 m
        │
        ├─► AnySat 支路：normalize_anysat（官方 DN 统计）→ [B,1,10,128,128] + dates
        │        → 两个 patch 尺寸（40 m / 160 m）→ dense [B,1536,128,128] ×2，stride 10 m
        │
        ▼
FeatureFusion：每路 1×1 投影到 C=128 + GroupNorm/BatchNorm + GELU
        → 按物理 stride 重采样到 10/20/40/80 m 四层 → 层内 softmax 门控 → 3×3 细化
        ▼
金字塔 P0..P3  [B,128,128,128] / [B,128,64,64] / [B,128,32,32] / [B,128,16,16]
        │
        ├─► SemanticAdapter：class_prototype(512) × vis_proj(P0) → 余弦×10 → sem_map [B,1,128,128]
        │                   class_prototype → MLP → FiLM(γ,β) [1,128]×2
        │
        ├─► CoarseLocator：FPN 自顶向下 → 粗 logits [B,1,128,128]（+ 0.1~0.35×sem_map）
        │                   presence [B,1]（当前 λ=0，未训练）
        │
        └─► FineRefiner：stem(P3) → 逐级上采样+跳连 → concat[P0(FiLM 调制), 粗概率, sem_map]
                         → 2×(3×3 conv+BN+GELU) → 1×1 → 细 logits [B,1,128,128]
        ▼
CombinedLoss = L_fine + 0.5·L_coarse + 0·L_presence + 0.1·L_region_text
   L_seg = 0.5·BCEWithLogits + 0.5·SoftDice，均按 valid 掩蔽
   L_region_text = 同一图内 FG 池化→1、BG 池化→0，与 class_prototype 的 BCE
        ▼
backward → AdamW(lr=1e-3) → clip_grad_norm(1.0) → step
```

冻结策略：TerraMind / AnySat / RemoteCLIP 文本塔全程 `eval()` + `no_grad`；
可训练仅融合、语义投影、粗头、细化器 = **3.5 M / 526.0 M**。

### 3.1 张量

| 名称 | 形状 | 单位 | 说明 |
|---|---|---|---|
| `x12` | `[B,12,128,128]` | DN 0–10000 | B01–B12（含 B8A），B01/B09 由同日 L2A 回补 |

| 波段 | B01 | B02 | B03 | B04 | B05 | B06 | B07 | B08 | B8A | B09 | B11 | B12 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

物理上合理：可见光低、红边/近红外高、SWIR 回落。

| 指标 | 实测 | 预训练期望 |

单块暗场景落在 −0.5σ 且在 0.04σ 量级波动。模型仍然能跑，但输入激活幅度远小于预训练时。

## 4. 语义信息长什么样

### 4.1 来源

不是用户输入，是代码里固定的 **1 条英文短语**：

```python
class_prompt = "a landslide scar in a satellite image"
```

模型构造时用冻结的 RemoteCLIP ViT-B-32 编码一次 → `class_prototype [1,512]`（范数 1.0，作为 buffer 常驻）。
属性原型当前 **shape = [0,512]，未启用**（`use_attributes: false`），因为数据集没有可核实的属性标注。

### 4.2 三条使用路径与实测

| 路径 | 实现 | 实测 |
|---|---|---|
| 粗定位调制 | `sem_map = cos(vis_proj(P0), proto)·10`，再乘可学习 `semantic_scale` 加到粗 logits | 初始化：`sem_map ∈ [−0.86, +1.57]`，std 0.30；语义项幅度 **0.248**，FPN 原始输出幅度仅 **0.0036**，总幅度 0.249 → **语义项占 99.6%** |
| 细化器 FiLM | `proto → MLP → γ,β`，调制 P0 | γ 平均 \|·\| 0.022，β 0.024（初始化接近恒等，不破坏特征） |
| 区域-文本 | 同图 FG 池化→1、BG 池化→0 | 初始化时区域嵌入与原型的余弦 ≈ **−0.04**（正交，符合随机投影预期） |

### 4.3 训练 60 轮之后

| 指标 | 初始化 | 训练后 |
|---|---|---|
| `semantic_scale` | 0.100 | **0.353**（模型主动放大 3.5 倍） |
| 语义项幅度 / 粗 logits 幅度 | 0.248 / 0.249 ≈ **99.6%** | 2.96 / 44.16 ≈ **6.7%** |
| `corr(粗 logits, sem_map)` | — | 0.192 |

**解读**：训练前视觉 FPN 头几乎是常数，语义相似度图是唯一有空间结构的信号；
训练后 FPN 自己学出了 43 的 logit 动态范围，语义退回到 ~7% 的调制角色。
模型确实"学会用语义"，但语义只提供边缘修正，不是主力。

## 5. TerraMind 输出：符合预期吗

| 项 | 实测 | 预期 | 判定 |
|---|---|---|---|
| token 形状 | `[2,196,384]`，14×14 | 224/16=14 → 196 ✓ | ✅ |
| 取层 | 2/5/8/11 四层 | 官方推荐 tiny/small/base | ✅ |
| 层间余弦（2→5→8→11） | 0.842 / 0.857 / 0.701 | 递减，层间有区分 | ✅ |
| 逐层 std | 0.78 / 0.78 / 0.88 / 0.81 | 非退化 | ✅ |
| TiM ON vs OFF | 相对差 **72.05%**，0.425 s vs 0.010 s | 明显不同 | ✅ TiM 真在执行 |
| **物理 stride** | 1280 m / 14 ≈ **91.4 m/token** | — | ⚠️ **太粗** |
| **token 空间自相关（lag-1）** | **0.118** | 相邻 token 应有相关性 | ⚠️ 很低 |

**结论**：形状、层选择、TiM 行为都符合预期；但**空间粒度是短板**——
一个 1280 m 图块只给 14×14 个 token，相邻 token 间隔 91 m 且相关系数仅 0.12，
意味着 TerraMind 分支几乎不携带细粒度空间信息。这与设计意图（由 AnySat 提供 10 m 细节）一致，
但如果指望 TiM 帮上边界，它做不到。**建议**：直接裁 224×224（2240 m）图块给 TerraMind，
避免 128→224 的上采样，让 token 对应 160 m 而非 91 m 的"假分辨率"。

## 6. AnySat 输出：符合预期吗

| 项 | 实测 | 预期 | 判定 |
|---|---|---|---|
| dense 形状 | 官方 NHWC `[2,128,128,1536]` → 转 `[2,1536,128,128]` | 对 s2 固定在 10 m 网格、2×D 通道 | ✅ |
| patch 数 | 40 m → 1024；160 m → 64 | 官方建议 ≤1024 | ✅ |
| 数值范围 | mean −0.0003，std 0.549 | 近似零均值 | ✅ |
| 通道活性 | 逐通道 std 中位 0.253；**4.2% 的通道 std < 0.01** | 少量死通道可接受 | ⚠️ |
| 两个尺度的关系 | 40 m 与 160 m 余弦 **0.425** | 不是冗余复制 | ✅ 互补 |
| 块结构（4 px / 16 px 边界跳变 vs 内部） | 0.00387 vs −0.0013（40 m）；0.00142 vs −0.00009（160 m） | 块内恒等是 dense 的固有性质 | ⚠️ 可见块效应 |
| 耗时 | 0.197 s / 0.099 s | — | ✅ |

**结论**：接口与尺度行为完全符合预期，两尺度确实互补（0.425 而不是 0.95）。
两个瑕疵：约 4% 的通道在单块上几乎恒定（需要多块统计确认是否为真死通道），
以及 dense 特征天然带 40 m/160 m 块边界——这就是之前可视化里"网格纹"的来源，
**不是 bug，是 AnySat dense 的定义方式**。

## 9. 该改什么（优先级排序）

1. **扩数据**（最高优先）：拉全 28 个分卷 → 5–10 个事件、每事件 ≥150 块。
   否则任何架构结论都不成立。
2. **TerraMind 输入方式**：改裁 224 原生图块（或 160 m token 对齐），
   不要 128→224 上采样后假装 91 m。
3. **输入标准化**：评估是否需要按块做稳健归一化（会偏离官方统计，需谨慎对照实验）。
4. **语义**：要么补真实属性标注，要么换更判别性的文本编码器；当前锚点太弱。
5. **负样本**：找"确认无滑坡"的图块，否则 presence / 空图拒检永远是 N/A。
6. 以上做完再谈 M3 消融。

## 11. AnySat dense 输出的真实结构（2026-10-18 查清）

### 11.1 网格不是配置错误，而是 dense 的构造

实测（italy 样本，patch=160 m，scale=16）：

| 通道段 | 块内 std（每 16×16 像素） | 判定 |
|---|---|---|
| 前 768 通道 | **0.00000** | 每个 patch 一个向量，块内**完全恒定** |
| 后 768 通道 | 0.622 | 真正的 10 m 局部特征 |
| 恒定通道数 | 正好 768（= 模型 D） | 与前一半完全对应 |

即 `output='dense'` 返回的是：

```
[B, H, W, 2D] = [ 上下文：每 patch 恒定（D=768） | 局部：10 m 特征（D=768） ]
```

**我们之前把 1536 通道整体当成 10 m 特征图**，于是那 768 个块恒定的通道必然在
patch 边界形成台阶——这就是"网格化严重"的直接原因。

### 11.2 已修正

融合改为按真实 stride 放置（`full_model.py`）：

| 来源 | 通道 | stride |
|---|---|---|
| `anysat.s2@40m.context` | 768 | 40 m |
| `anysat.s2@40m.local` | 768 | 10 m |
| `anysat.s2@160m.context` | 768 | 160 m |
| `anysat.s2@160m.local` | 768 | 10 m |
| `terramind.S2L2A` | 384 | 91 m |

来源数从 3 个变成 5 个，上下文段不再被强行放大到 10 m。

### 11.3 但残差仍在

局部段本身在 patch 边界也有台阶：跨块跳变 0.736 vs 块内 0.337（比值 **2.18**）。
说明 AnySat 的"10 m dense"并不是一张连续的高分辨率特征图，而是
**10 m 网格上、以 patch 为单位条件化**的特征。

因此有两件事要说清楚：
1. **不能用它替代真正的高分辨率特征**（如 TerraMind 之外的 10 m 编码器）；
2. 它的正确用法是"多尺度上下文"——patch 级向量按 patch 尺寸放，这正是 11.2 的改法。

### 11.4 对"是否还要用 AnySat"的判定

- 上下文段（768ch @40/160 m）仍然有价值：它提供 TerraMind 给不了的局部邻域上下文；
- 局部段（768ch @10 m）要单独做消融，确认它比 TerraMind 上采样多带来多少信息；
- 在完成这两项之前，不能声称"AnySat 提供了 10 m 细节"。
