
## 2. 第一次跑：训练收敛，但 test 几乎为零

```
损失：前 10 步 1.176 → 后 10 步 0.290（最低 0.162）

```

训练样本从 26 涨到 80、事件从 2 个涨到 5 个，**test 几乎没有变化**。

## 3. 诊断：预测全堆在无效像素上

把 test 样本的预测图逐像素拆开看（3 个 italy 样本）：

| 样本 | 无效像素比例 | 预测 >0.5 的像素里落在无效区的比例 | 无效区平均 prob | 有效区平均 prob |
|---|---|---|---|---|
| italy_2206 | 3.1% | **100%** | 0.99 | **0.00** |
| italy_2203 | 3.1% | **100%** | 0.91 | **0.00** |
| italy_1835 | 3.1% | **94%** | 0.83 | **0.00** |

看 `fix_before_after.png` 的左起第三列：概率图整片深紫（≈0），只有**右边缘一条亮带**。
也就是说模型把全部"正例"押在了无效像素上。

**根因**：B01/B09 回补窗口在边界有 nodata，装配时保留了 0 值。这些像素：

1. 输入是 0（极端暗值，分布外）；
2. 又因为 `valid=False` 被排除在损失之外 —— **在那里错了不罚分**。

于是模型学会了"把概率倒在无监督、且输入异常的像素上"，这在损失上是最省事的解。

---

## 4. 修复

| 位置 | 改动 |
|---|---|
| `data/certified.py::load_sample` | 用最近邻（`distance_transform_edt`）填补 B01/B09 的 0 值空洞；`valid` 掩膜保持不变，监督仍排除这些像素 |
| `models/full_model.py::predict` | 新增 `valid` 参数，输出概率乘以 valid |
| `training/trainer.py::evaluate` | 评估同样按 valid 置零 |

## 6. 现在的结论

1. **训练链路是通的**：5 个事件、80 个样本，loss 从 1.18 降到 0.16，val 上能做到 IoU 0.23–0.26。
2. **italy 是真正的域外**：模型在有效区几乎不输出任何正例（prob≈0.00）。
   同一模型在 hiroshima 上能给出位置大致正确的斑块（见 `train_pred_check.png` 下两行）。
   所以这不是"完全没学会"，而是"学到的形态不适配意大利的农田—丘陵场景"。
3. **数据量仍是主要瓶颈**：80 个训练块、5 个事件，且 156 个样本里 italy 占了 40 个（全给了 test）。
   可训练的正样本合计不到 3 万像素。

## 7. 下一步建议（按性价比排序）

1. **把 italy 从 test 里放出来一部分**：现在训练集里没有任何"农田+丘陵"场景，模型没机会见过。
   建议改成 5 折事件交叉验证，而不是单次留出。
2. **补负样本**：意大利的误报主要来自边界与裸地，若有"确认无滑坡"的图块，可显著压 FPR。
3. **继续扩样本**：把 remaining 18 个分卷拉全，认证到 400+ 样本再谈结论。
4. **再谈消融**：当前精度水平下，任何模块的贡献都会被域偏移淹没。
