## 0. 总指令

不是来对现有 SegFormer 连续叠加小模块，而是要**定位并改善当前低 IoU 的根因**。请先阅读整个项目、现有训练入口、数据构建逻辑、历史日志和报告，再实施以下任务。

**执行原则**

1. 保留原有 v1、v2_clean、v3、所有历史 checkpoint、日志、manifest、输出及其哈希；新结果放入独立版本目录，禁止覆盖。
2. **先让更多真实且有效的训练数据进入 SegFormer，再评估它是否具有随数据增长持续提升的能力。** 在此阶段冻结结构，主用 `direct10 + Spectral Stem`，同时保留无 Stem 的 direct10 作为必要对照。
3. 论文官方数值与当前项目数值必须按照**数据版本 / split / 输入模态 / 时间步数 / 标签 / 指标口径**分别列示；没有全部对齐前禁止直接排名。
4. 严格区分：官方随机分层 benchmark、项目原始事件 OOD、重新设计的事件 OOD、同事件空间留出、使用未标注目标域的适应实验。
5. 增加数据时必须报告 **新增训练样本、独立训练事件、标签可信度、前景像素占比、背景类型、可靠负样本**，而不只报告下载文件数量。
6. 每组对照只改变明确列出的因素。数据扩量、改变时间选择、raw/harmonized、负样本加入、训练预算、损失与网络架构都不可无记录地同时变化。
7. 先做单 seed **可行性和诊断**；具有研究结论价值的组运行历史相同的 3 seeds（`1234/2026/3407`）。不得把单 seed 的最高值称为证明。
8. 在所有阶段，记录完整 train/val 指标、每事件结果、每尺度对象召回、误报、PR-AUC/AP、训练成本；切勿只汇报最佳 IoU。
9. 运行中遇到源数据不足、数据权限、显存、依赖或协议冲突，先查明并留证；允许降级成明确标注的可执行子实验，不允许静默代换数据或伪造结果。
10. 先完成可用的实施、单元测试、审计及轻量试运行。**不等待用户对每个细节反复确认；但不要在关键数据协议未通过审计时启动正式批量训练。**
11. 不要把本文中建议的脚本名当成项目已经存在的文件；应先检查现有代码，优先重用框架，尽量减少重复实现。

逐项阅读并在报告中引用/记录确切来源、版本、对应代码路径：

**重要口径：**

- 2026-10-19 检索到的官方仓库 README 中，`S12LS-LD` / harmonized / S2 + DEM / 3 seeds 的前景 IoU（按表格百分数转小数）分别约为：U-ConvLSTM **0.4488**、U-Net3D **0.4166**、ConvGRU **0.4191**、U-TAE **0.4474**；README 报告训练 75 epochs。
- 论文摘要与实验表有高于 **0.83 的 F1**，但仓库特别说明论文中存在**macro-average** 与后来补报的**滑坡前景 binary 指标**的差别；不要把 0.83 理解为前景 IoU，也不要与本项目 IoU 直接比较。
- 论文技术验证部分的训练细节、早期 Hugging Face README 和**当前 GitHub README**在 epoch、数据版本或数值上可能不同。请记录每个来源的**文件修订/commit 或下载日期**，统一之后才做复现。
- 官方论文**Experiment 3**进行了六个地理群组的 leave-one-cluster-out 检验。欧洲对应 Italy；该实验含全量/筛选测试集之分（还对无标注图块进行了筛选），模型与输入也不同。独立重建这部分口径，不能把其 F1 与项目 strict OOD 的 IoU 混用。
- 官方 `S12LS-LD` 为监督滑坡检测的**有标注正图块任务子集**；完整 S2 为 **13,628** 图块，其中 **6,737** 为带注释图块，任务子集 S2 为 **4,988**。所谓“无滑坡注释”不等于已穷尽核验为无滑坡。
- 官方数据同时提供 `raw` 与 `harmonized`；后者对 2022-01-25 后的 S2 Baseline 04.00 **+1000 DN 偏移**等进行处理。核对现有样本实际版本、值域和读取流程；不能把混用数据源的问题当作普通归一化问题。

**输出文件：** `reports/P0_official_benchmark_protocol.md`；至少含官方版本、split、训练集规模、每个模型的时间步数、S2/DEM 通道、标签版本、训练轮数、损失、指标定义、结果及与本项目的差异表。

## 2. 评价体系：先锁定，再用整个阶段

### 2.1 不得混用的四类协议

| 协议 ID            | 数据/任务                                            | 目的                             | 是否可以代表未知事件泛化              |
| ---------------- | ------------------------------------------------ | ------------------------------ | ------------------------- |
| `BENCH_OFFICIAL` | 官方 `S12LS-LD` 指定版数据与官方 split；另外注明单期 vs 官方多时相+DEM | 官方可比性和输入能力诊断                   | **不可以**自动代表跨事件            |
| `OOD_LEGACY`     | v3 固定的现有 Train/Hiroshima/Italy 划分                | 与旧模型回归比较，Italy 为已反复使用的**开发诊断** | 可以作为开发 OOD，不是最终盲测         |
| `OOD_V4`         | 新建整事件/整 inventory 互斥 split；多独立开发验证事件 + 新最终留出事件   | 后续核心跨事件比较                      | 只有真正预留的未参与选择事件才是最终测试      |
| `SPATIAL_ADAPT`  | 同事件空间块互斥，允许目标域数据进入训练                             | 判断同事件局部域适应价值                   | **不可以**称 strict event-OOD |

后续如使用**未标注目标事件图像**做预训练，要再建 `UDA_OOD`，独立于 `OOD_V4` 的“目标事件不可见”严格协议。

### 2.2 OOD_V4 划分硬约束

1. 先在完整事件列表上确定拆分，**再**计算归一化统计与训练子集；不允许看到模型分数之后移动事件。
2. 避免同一 `event_id`、同一 inventory/polygon 及空间相邻泄漏；列出空间隔离规则、实际距离和泄漏检查结果。
3. 开发验证应尽量含多个独立事件；如果事件数/区域分布不足，使用按事件留一的开发折并明确限制，不把折内结果当全新盲测。
4. Italy 已被用于大量模型筛查，只用于诊断。早期进入过训练/方案讨论的其他事件不能被无条件称为“历史上从未使用的盲测”；在剩余未使用事件中预先选择保留集，若根本不存在，坦诚标注“新的冻结测试协议”，不宣称严格历史盲测。
5. 不对无注释图块直接赋 0 标签；负样本应使用可追踪证据确认。不能将多事件质量差异隐藏在整体 pooled IoU 中。
6. 冻结 1 份只读 `split_v4.json` 与哈希。**P1 扩量只能从 TRAIN_CANDIDATES 取数据，不可跨入任何 val/test**。如果在固定留出下根本无法明显增加训练量，必须报告这一事实并重建全新的、前后版本一致的实验协议，不能偷拿 Italy 提升数字。

### 2.3 指标和日志

**主指标：** 前景 pooled IoU（阈值固定 0.5）、前景 Dice/F1、Precision、Recall；按事件等权 macro IoU、最差事件及逐事件表。

**诊断：** PR-AUC / Average Precision（由有效像素上的概率和标签计算）、0.1～0.9 阈值 PR 曲线但不得在 OOD test 上选最终阈值、预测概率直方图、FP 面积、可靠负图块 FP per tile、每 10^6 背景像素 FP、可见性与类别不平衡的分层统计。

**对象：** 8 邻域匹配；面积档 `1–4, 5–9, 10–19, 20–49, 50–199, >=200 px`；按 GT→预测一对一匹配（主诊断 IoU 匹配门槛沿用 0.25），截边目标单列，报告对象 recall 和每幅 FP 对象数。

**边界：** 1 像素容差 Boundary F1，需报告单位和 valid 区域处理。

**口径细则：**

- 背景图块的前景 IoU 若联合像素数为零则为**未定义**，不要以人为的 1.0 拉高 macro IoU；可靠负样本以 FPR/FP 另行报告。
- 事件宏平均中没有前景的纯负事件不参与正类 IoU 均值，但仍计入误报表。
- 报告 per-event TP/FP/FN、样本数量、前景像素总数，任何汇总都能重新计算。
- 总体结果必须同时提供 **3-seed mean±std**、每个 seed 原始值、训练时间、显存、参数量；事件数量足够时提供按事件聚类 bootstrap 的不确定性估计，否则说明其不稳定性。

## 3. P1：第一核心任务——SegFormer 数据规模与数据质量研究

**核心假设 H1：** 当前性能受训练样本/事件覆盖/标签质量影响，现有 SegFormer 尚未充分释放学习能力。  
**备择解释 H2：** 即使增加有效数据，模型在完整 Train 与 OOD 上仍较早平台，表明输入、表征、优化或标签任务定义存在其他瓶颈。

### P1-0：冻结模型与主训练设置

用原代码已验证可运行的：

- `SegFormer-B0 / direct10 / Spectral Stem`；
- 对照 `SegFormer-B0 / direct10 / no Stem`（仅指定核心对照重跑）；
- 预训练 checkpoint `nvidia/segformer-b0-finetuned-ade-512-512`（在 P0 复核一致性和输入层初始化）；
- BCEWithLogits + Dice、AdamW、当前编码器/新层不同学习率、初始权重、valid 处理、batch 规模与历史配置尽量一致；
- 随机种子 `1234/2026/3407`；主阈值 0.5。
- **不添加** AFF、条件粗细头、语义文本、DEM、SAR、时相堆叠、对比学习损失等新变量。

**训练预算要分别清晰记录：**

- **主公平对照（fixed-update）**：同一 optimizer steps、相同学习率调度策略和有效 batch；记录小数据集重复曝光次数/样本覆盖。
- **补充收敛对照（fixed-exposure / same-epoch）**：让各 N 档至少经历可比的数据曝光轮数，训练步数可以不同；单独报告，不和 fixed-update 结果混算。
- 仅用开发验证选早停、最佳 checkpoint，不使用 Italy 或冻结最终测试。

### P1-1：建立 v4 训练候选池

Codex 必须先实地盘点完整可获取的官方 S2 及当前原始文件，评估以下候选，不能预设全部可用：

1. 当前 `v3 train` 中已通过数据契约的图块。
2. 官方 `S12LS-LD` / 其他已标注 S2 数据中属于**允许训练事件**的图块。
3. 原项目此前因未下载、分卷缺失或非必要筛选而漏掉的合法训练图块。
4. 对 SCL、时相和事件日期尚需审计的样本：分级，不直接混入主要训练集合。
5. 真正可靠的负图块或困难背景：先独立列池，暂不与 P1-2 主纯正图块学习曲线混合。

输出一个能对账的表：

| 类别 | 需要统计                                        |
| -- | ------------------------------------------- |
| 原始 | S2 文件、样本 ID、文件版本、可用时相                       |
| 质量 | 有效观测比例、影像与标签可见性、排除原因                        |
| 标注 | 像素比例、对象数与面积分层                               |
| 地理 | event/inventory/区域、近邻与同 polygon             |
| 用途 | 允许 train / 固定 val / 冻结 final / 诊断 / exclude |
| 扩量 | 相对原 v3 train **净新增训练图块数及新增独立事件数**           |

如果无法在不污染留出集的前提下显著增加训练数据，要明确写为 **DATA_LIMITED**，说明所缺事件和潜在替代数据；不能把测试图块转训练后仍称为原严格 OOD。

### P1-2：单模型嵌套学习曲线——仅改变训练数量

在 `OOD_V4` 固定训练候选事件中使用嵌套样本池，候选规模为 **25%、50%、75%、100%** 可用训练数据。

执行要求：

- 各档严格嵌套，随机种子固定，**不同规模中的事件组成尽量按相同权重分层**，同时记录是否有某些事件在小规模档缺席。
- 优先使用**有标注正图块**，保持负图块引入方式相同（第一轮可不引入额外负图块），避免“数据量增长”和“负比例变化”混淆。
- 每档先 seed 1234；验证配置稳定后运行 3 seed 核心学习曲线。
- 主做 `SegFormer-B0 direct10+Stem`；小规模与全规模两端至少增加 `no Stem` 核心对照。
- 不同样本量须报告独立图块数、正前景像素数、事件数、每事件样本占比、有效 train IoU、开发 val/OOD IoU。
- 以**同一组评估图块**绘制 Train、开发验证、Italy 诊断的学习曲线；Italy 只能画固定诊断结果，不能用于筛选。

**额外对照（很重要）：** 在 `OOD_LEGACY` 完全固定的既有 val/test 上，再执行一份“仅从合法 train 候选补充数据”的 v3→v4 比较；如果合法增加不可行则标注跳过。这样才能将“新的 OOD_V4 组内实验”与“历史数值的回归对比”分开。

**实验 ID：** `P1_SIZE_{25,50,75,100}_B0STEM_seed####`；训练预算版本后缀 `_fixedsteps` 或 `_fixedexposure`。

### P1-3：数据量还是**事件多样性**？

如果训练候选池涵盖足够多事件，抽取**近似相同训练图块总数 N**（以合法事件数决定实际 N），做：

- `P1_EVENT_FEW`：来自较少事件的图块；
- `P1_EVENT_MORE`：来自更多事件，每事件取样更少；
- `P1_EVENT_ALL`：尽可能覆盖全部许可训练事件。


N、总前景像素比例和面积档尽量匹配；若做不到，记录残余差异并避免强因果结论。开发验证事件保持不变。

**回答：** 需要的是更多“同类图块”，还是跨地貌、植被和滑坡形态的事件覆盖？将“增加 1000 张同事件图片”和“增加一个新灾害事件”区别开。

### P1-4：数据质量独立消融

固定图块 ID 与事件集合，只改变一个已验证的数据处理维度：

| 对照 ID       | 变化                              | 约束                                   |
| ----------- | ------------------------------- | ------------------------------------ |
| `Q_SOURCE`  | `raw` vs `harmonized` **同图块配对** | 各自一致处理，不允许两版本混训；确切保留 source revision |
| `Q_DATE`    | 官方可重现单期选取规则 vs 当前灾后清晰时相规则       | 必须只用可观察质量和事件日期，**不能按 GT 匹配程度选择时相**   |
| `Q_QUALITY` | 样本有效性阈值/可见性高可信子集                | 要额外记录丢弃样本造成的训练 N 差异；必要时同 N 配对        |
| `Q_NORM`    | 训练集波段标准化的当前实现 vs 经核验的物理一致实现     | 同固定输入、同数据 ID；绝不从 val/test 计算均值方差     |

先做审计与极少量训练；只有发现不同数据版本或规则对性能形成实质影响，才扩成多 seed 正式结果。不能把主实验中的性能提升直接归因于其中某个数据质量因素，除非有配对对照。

### P1-5：可靠负样本 / 困难背景（完成正图块规模主实验后）

按独立证据将可用负样本分为：

- 高可信、已核实无滑坡的图块；
- 有裸土、道路、河床、采石/人工开挖等复杂背景的高可信困难负例；
- 未标注但存在潜在漏标风险的图块（**禁止作为真负样本参与监督**，可用于后续自监督）。

对照（正图块集和总训练预算不变，清晰记录加入的负图块数量）：

1. `NEG0`：仅当前有标注图块中的有效背景，复制 P1 主设置。
2. `NEG1`：加入可靠普通负图块。
3. `NEG2`：加入可靠普通负图块 + 困难负图块。

对含可靠负图块的独立开发集合，分析 FP objects/tile、背景 FPR、前景 Precision、Recall 变化；**不得只看 IoU 改善而忽略召回下降**。

### P1-6：训练能力与误差机制诊断

对 P1-2 最小与最大数据档保存同一口径的：

- **完整训练集**、多个开发验证事件、Italy 诊断的学习曲线；
- 每 epoch train loss / train pooled IoU / val pooled IoU（训练 IoU 分别记录 augmentation-on 与干净推理验证时的版本）；
- PR 曲线与 AP、0.5 阈值召回；
- 预测概率分布，GT vs background；
- small/medium/large + 细分档漏检；
- 背景混淆图（道路、河床、裸土、建筑、云影，必须以人工审计为依据）；
- 过度细长/截边 GT 对象误差。

其中，**Train IoU 低不能单独证明欠拟合**，必须同时核对有效标签、优化是否收敛和输入是否可观察；Train 高而 OOD 低也不能单独证明某一种域差异原因。

### P1-7：官方条件单期对照（与主 OOD 研究分开）

为了回答“官方模型为什么远高于当前结果”，使用官方 `BENCH_OFFICIAL` 的固定数据与 split，完成最少两项对照：

- `B-SINGLE`：**相同官方样本 ID / 官方 split**，选一个规则固定的单期 S2，仅 10 波段 SegFormer-B0（推荐先无 Stem 与 Stem 中至少一种）；
- `B-TEMP`：尽可能用官方代码、官方输入与设定运行一个**多时相 S2 + DEM**的官方基线（优先资源可承受的 3D-UNet / U-TAE）。先直接调用官方提供的参数/检查点或脚本复算评测，再视计算资源做复训。

必要时增加：

- `B-SINGLE-DEM`：同一单期 S2 + DEM，测试加入地形本身的影响；
- `B-MULTI-NODEM`：同一多时相 S2 但无 DEM，测试时间信息的影响。

本节是**可观测信息/论文可比性实验**，不能把多时相模型成绩直接称为单期 SegFormer 的缺陷。若训练官方基线资源不足，可先完成官方评测重现及协议差异报告，并明确 `not_reproduced`。

### P1 实验优先级与预算控制

**第一批（必须做）：** P0 → P1-1 → P1-2（可用 N 的学习曲线）→ P1-6（全量 train/val/OOD 诊断）。  
**第二批（按数据可用性）：** P1-3（事件多样性）、P1-7（官方同协议）、P1-4（发现可疑预处理时）。  
**第三批（可信负样本具备后）：** P1-5。

正式运行不需要在所有组合上做笛卡儿积；诊断实验单 seed，用最少对照排除不可行分支；核心结论需要 3 seeds。记录选择了哪些试验、跳过了什么以及为何跳过。

### P1 判断 / 阶段出口

把下列结果分类（不要用主观“看起来还行”替代证据）：

| 观测结果                                          | 优先解释                 | 下一步                 |
| --------------------------------------------- | -------------------- | ------------------- |
| 更多合格训练数据让完整 Train、多个独立 OOD 事件的 IoU / AP 均持续提升 | 数据量/覆盖可能是主限制         | 扩大数据与事件覆盖，同时比较编码器   |
| Train 高、Hiroshima 高，未知事件普遍极低；事件多样性比单纯 N 有效    | 地理分布依赖/捷径学习可能显著      | 进入 P2 + P3 域泛化线     |
| 不论数据量，完整 Train 和同分布 val 也长期偏低；优化/标签审计通过       | 现有模型表达、预训练或优化能力需重点检验 | 优先 P2               |
| 单期弱，但官方单期同协议也弱；官方多时相+DEM 显著更高                 | 输入信息可能是主要约束          | P3 输入充分性对照          |
| 更新 harmonized 或标签可见性规则后结果变化大                  | 存在数据/评测质量问题          | 冻结修复版本，**重建所有相关基线** |
| 只在 Italy 获益或误报大幅上升                            | 不能证明泛化改善             | 保留负/不稳定结果，勿作为主线升级   |

研究成功**不能只看一个固定的数值阈值（如 IoU>0.5）**。至少需要多个独立事件方向一致、正类指标和误报共同改善、3-seed 可复现，且协议无泄漏。

**P1 交付：**  
`P1_learning_curve.csv`、`P1_event_diversity.csv`、`P1_quality_ablation.csv`、`P1_official_comparison.md`、`P1_error_atlas/`、`P1_summary_and_next_decision.md`。

## 4. P2：多编码器表征能力竞争实验（P1 得出第一轮结论后启动）

**目的：** 分清数据量/训练域不足与模型表征或容量不足；不能用复杂融合结构掩盖编码器对照。

### P2-1：候选优先级

| 优先序    | 编码器                                      | 对照意义                | 注意                                                            |
| ------ | ---------------------------------------- | ------------------- | ------------------------------------------------------------- |
| M0     | 现有 SegFormer-B0 direct10 + Stem          | 已有主基线               | 保留原模型权重、预处理、10 波段                                             |
| M1     | SegFormer-B2 direct10                    | 在相近架构族内检验容量/预训练层级变化 | B2 输入初始化须与 B0 同原则，训练预算合理匹配                                    |
| M2     | DOFA / 官方稳定 checkpoint                   | 检验波长感知的多光谱特征        | 先验证官方波长映射、checkpoint 与特征输出，禁止乱填波长和频段                          |
| M3（备选） | DINOv3 卫星版本 / Prithvi-EO-2.0 / TerraMind | 检验通用自监督或地球观测预训练     | 各自支持的波段/原生分辨率不同；单独报告输入不等价，不能把 6-band 与 10-band 当完全公平的唯一“架构”差异 |
| Cost   | 现有 U-Net/ResNet18                        | 轻量成熟 CNN 成本参照       | 重跑统一 v4 协议，历史单 seed 不能替代                                      |

初期控制总候选数：**M0、M1、M2**；如 DOFA 接口/权重不可用，先以成本参照或已验证可用的强编码器替换，明确原因。不要同一时间把 Prithvi、AnySat、TerraMind、CLIP、SAM 全部融合。

### P2-2：二层对照

**A. 冻结特征 probe**

- 冻结所有编码器；读取可靠 GT 区域内的特征与前景/背景标签；
- 使用相同结构和容量的轻量 segmentation head（若特征分辨率不同需统一投影和上采样方式；同时报告各自原生特征 stride）；
- 训练同等步骤，只更新 head；
- 输出各编码器的 train/开发事件/Italy 的前景 IoU、AP、每面积档召回；
- 必要时增加只针对可核实像素/对象的 linear probe，避免背景泄漏和空间近邻独立性误判。

**B. 完整微调**

- 相同输入任务、主数据池、OOD_V4、指标和 seed；
- 各编码器使用**合理且记录在案的学习率/优化参数**，不得用故意不适配的公共超参让某模型失败；
- 比较相同 optimizer steps **及**达到收敛所需成本；参数量、GFLOPs、显存、推理延迟单列；
- 不同输入通道数/空间采样率/预训练来源必须在结果表注明，额外设 6-band SegFormer 子对照以区分 Prithvi 等模型的输入影响。

### P2-3：判断依据

- 冻结特征跨事件已经更强：说明预训练表示有帮助，后续可考虑多尺度/语义，但先验证重复稳定性；
- 冻结相近、微调不同：检查优化配置、容量和监督适应，不立即归因于预训练；
- 只在 train 上更强：大容量可能过拟合，优先改训练域和正则；
- 编码器都不理想：继续考虑标签可观测性、任务输入限制和 P3。

**交付：** `P2_encoder_registry.md`、`P2_probe_results.csv`、`P2_finetune_results.csv`、`P2_compute_cost.csv`、`P2_encoder_recommendation.md`。

## 5. P3：仅按前面证据开启的拓展方向

**P3-A 自监督/半监督（先验证，不立即整合）：**  
在未标注的多区域 S2 数据上测试成熟的 masked modeling / 同类方法，再以固定标注数进行单期滑坡分割微调。绝不能使用目标域未标注影像后仍称“从未见过目标事件”；分别汇报 strict OOD 与 UDA_OOD。

**P3-B 跨事件学习策略：**  
利用 P1 对照判断是否需要事件均衡采样、受限的物理合理光谱扰动、困难负样本及场景覆盖；优先测试能解决已见失败类型的机制，而不是直接再上 AFF。

**P3-C 信息充分性：**  
在相同地理图块、匹配评测下对照单期 10-band、单期 S2+DEM、多时相 S2、多时相+DEM。目的是估计额外观测提供的信息增量，不能把不同输入模型和 strict 单期主线混为同一榜单。

**P3-D 语义/语言与复杂融合：**  
在稳定视觉基线与对象级真实属性标注成立后再做无语义/类别词/可信属性/打乱属性实验。只有验证确有独立贡献，才尝试 TerraMind、AnySat 或其他跨模态特征融合。
